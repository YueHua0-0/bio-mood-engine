## 1. 背景与目标
前面的模块都能单独跑通，但"每个模块正确"不等于"组合起来稳定"。本任务书建立一套**可重复、可复现、可量化**的测试基线，回答三个问题：同样的输入是否永远得到同样的输出；跑一年会不会数值漂移或爆炸；插件在有故障、有隐私约束的宿主里是否仍然安全。

所有测试数据、仿真曲线与阈值均为**虚构角色状态模拟**，不是人体医学模型，不用于诊断、治疗或现实健康预测；测试报告不得把模拟结果表述为健康结论。

### 1.1 关键约束（摘自 00，不得改动）
- 纯函数测试不得依赖系统时间、真实网络、真实文件系统之外的本机存储；时间一律显式传入。
- 所有 `[0,1]` 字段在任意时刻无 `NaN` / `Infinity` / `-0`（I1）。
- 相同状态 + 输入 + `now` + 种子 + 版本 → 相同输出（I5）；`state_version` 单调（I2）。
- 测试只使用 Node 内置 `node:test` / `node:assert`，不得引入第三方库。
- 测试失败必须输出可复现的种子、输入摘要与失败断言，不得只打印"失败"。

## 2. 范围与非目标
**范围**：六类测试目录的职责划分；17 类测试矩阵；自写属性生成器；确定性与跨进程一致性；幂等与并发；时间/时区/夏令时/回拨；持久化与重启；版本迁移；契约快照；性能基线；故障注入；隐私扫描；提示注入；边界值；90 天与 365 天长期仿真；覆盖率与稳定性；测试报告。

**非目标**：不实现业务算法；不修 bug（发现问题交回对应模块）；不做 UI/端到端联调（15）；不追求 100% 覆盖率；不搭建 CI 服务；不生成压测集群。

## 5. 算法与规则

### 5.1 属性生成器（不引第三方库）
```text
forRandom(seed, n, fn):
  s = seed >>> 0
  for i in 0..n-1:
    s = (Math.imul(1103515245, s) + 12345) >>> 0      // LC-G，固定常量
    value = s / 0x100000000                           // [0,1)
    try fn(value, i)
    catch e: 输出 {seed, i, value} 后 rethrow          // 失败必带可复现种子
```
- 种子必须由用例常量提供，禁止 `Date.now()` 或随机种子；
- 同一 `seed + n` 必须产生完全相同的序列；生成器本身要有单测；
- 每个属性用例至少 200 组输入，关键不变量（I1/I2/I7）至少 1000 组。

### 5.2 确定性
| 项 | 规则 |
| --- | --- |
| 同进程 | 同输入 + 同种子 + 同版本连跑两次，`stateFingerprint` 必须相等 |
| 跨进程 | 子进程运行同一 fixture 两次，输出 JSON 摘要逐字节相等 |
| 随机隔离 | 只让 `mood` 多取 10 个随机数，`cycle` / `sleep` 结果不得改变（I6） |
| 时间 | 引擎不得读系统时间；测试用 `fixedClock` 注入 |
| 顺序 | 模块注册表顺序固定，重排注册应抛错 |

### 5.5 性能基线（普通笔记本）
| 基准 | 目标 | 测量方式 |
| --- | --- | --- |

## 6. 边界与错误
| 场景 | 处理 | 错误码 / 行为 |
| --- | --- | --- |
| 属性用例失败 | 打印 `seed/i/value` 并失败 | 断言失败 |
| 断言只比较字符串 | 拒绝（须比较结构化对象） | 测试代码缺陷 |
| fixture 缺失或损坏 | 立即失败，不跳过 | `ENOENT` |
| 覆盖率低于目标 | 报告标红，不静默通过 | 门禁不通过 |
| 性能超基线 10% | 记录并阻断 G4 | 门禁不通过 |
| 仿真出现 `NaN` | 立即中止并保存最后 10 步 | S1 失败 |
| 用例依赖真实时间 | 静态检索命中即失败 | 静态检查 |
| 连续 10 次出现 1 次失败 | 判定 flaky，禁止发布 | G4 不通过 |
| 测试访问网络 | 直接失败（无网络桩） | 静态检查 |
| 阈值被放宽以通过 | 视为篡改契约 | 回退并上报 |

## 10. 禁止事项
1. 禁止引入任何第三方测试库、断言库或 mock 框架；只用 `node:test` / `node:assert` / `node:crypto`。
2. 禁止用 `Date.now()`、`new Date()`、`Math.random()` 作为测试输入或等待条件；时间必须显式注入。
3. 禁止用 `setTimeout` / `sleep` 等待异步完成；必须用确定性钩子或 `await`。
4. 禁止访问真实网络、真实微信、真实账号数据；fixture 必须是脱敏合成数据。
5. 禁止为了让用例通过而放宽契约阈值、跳过断言或注释掉失败用例。
6. 禁止在测试中修改 `lib/**` 或 `00`–`13`；缺陷如实上报。
7. 禁止把真实聊天正文、wxid、令牌、完整种子写入 fixture 或报告。
8. 禁止只提交"全部通过"式报告，必须附实际数字与失败项。

**§10.2/§10.3 的允许清单（P-14-05，裁决 A：仅测试脚手架，引擎零命中）**

以下 `tests/**` 命中是脚手架度量或被测对象的外部替身，不是引擎时间输入，§9 的检索命令用 `Where-Object` 排除：

| 文件 | 命中 | 为何允许 |
| --- | --- | --- |
| `tests/integration/plugin_hooks.test.mjs` | `setTimeout` 模拟 DSH 慢调用；`Date.now()` 断言钩子 800 ms 预算 | 外部依赖替身 + 性能断言 |
| `tests/integration/plugin_manifest.test.mjs` | 覆写 `globalThis.setTimeout` / `clearTimeout`；`Date.now()` 量 setup 耗时 | 「插件不得注册定时器」的反例用例，必须触及计时器 |
| `tests/unit/coordinator.test.mjs` | `setTimeout(10 ms)` 让出事件循环 | 构造互斥锁并发交错 |
| `tests/unit/_api_helpers.mjs` | `req.setTimeout(timeoutMs, ...)` | Node `http` 客户端超时，非注入计时器 |
| `tests/integration/plugin_package.test.mjs` | 用例标题里出现检索词本身 | 自指的静态检索用例，必须写出模式串 |

另外两类命中按规则过滤，不算豁免：**注释行**（`//`、`*`、`/*` 开头的说明文字，如 `lib/modules/cycle/advance.mjs:7`、`tests/unit/regulation_targets.test.mjs:62`）由 `$_.Line -notmatch "^\s*(//|\*|/\*)"` 排除。

**门禁范围**：`tests/**` + 引擎（`lib/core`、`lib/modules`）。`lib/api`、`lib/storage`、`plugins/**` 是宿主边界，按 12 §5.5/§6.0 合理使用 `setTimeout`（重试退避、请求超时、socket 兜底）与 `Date.now()`（日志 `duration_ms`）；它们的引擎时间输入仍由注入的 `clock` 提供，不在本门禁内。新增豁免必须先在台账登记。

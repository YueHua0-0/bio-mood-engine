## 1. 背景与目标
外部互动必须先变成"可量化、可衰减、可追踪"的压力，再交由情绪引擎统一消费。本模块负责这条链路的前半段：把一条微信事件转成有符号强度，叠加关系倍率，按固定时间常数衰减，合并短窗口内的重复刺激，并维护 `stress.level` 与 `stress.active_events`。本模块只写 `stress.*`，不写任何 `mood.*`，使 I7 在结构上成立。全部数值、事件与关系标签均为**虚构角色状态模拟**，不是人体医学模型，不用于诊断、治疗或现实健康预测。

### 1.1 关键约束（摘自 00，不得改动）
- 9 种 `event_type` 的基础强度冻结为 0.02 / 0.08 / 0.12 / −0.10 / 0.25 / 0.05 / 0.06 / 0 / 0。
- `relationship_tag` 只允许 6 个值；未知一律 `unknown`，不得根据正文猜测。
- 单次 `stress.level` 变化 ≤0.30；`active_events` ≤32 条；只保留有效 `remaining`。
- 事件正文、原始 wxid 不进状态与日志；同一 `event_id` 幂等，同源短窗口合并不做简单相加。

## 2. 范围与非目标
**范围**：强度与倍率计算；五档衰减与 `remaining`；300 秒同源合并；压力目标与半衰期趋近；`active_events` 去重/排序/截断/剔除；`long_silence` 与每日上限。

**非目标**：不做关键词或语义情绪分析；不判断消息重要性（由适配层给 `relationship_tag`）；不决定交付与唤醒（11）；不做情绪合成（09）；不实现持久化与跨请求幂等（04）；不新增状态字段。

## 4. 输入 / 输出
### 4.1 函数签名
对应 02 §5.5 流水线第 3、4 步，两个入口共享同一套纯函数：

```js
export function updateStress({ previous, inputs, now, rng, config }) {}   // 第 3 步：只衰减
export function applyEvent({ previous, inputs, now, rng, config }) {}     // 第 4 步：只应用事件
export function baseIntensity(et) {}
export function relationshipMultiplier(tag) {}
export function computeIntensity(event) {}   // 另含 remainingAt / mergeEvents / targetStress
```

`updateStress` 的 `inputs.event` 必须为 `null`；`applyEvent` 必须携带 `inputs.event`。协调器按 02 §5.5 注册，不得交换顺序。

只有 `applyEvent` 可以返回 `derived.event_intensity`（00 §4.2 白名单，见 §4.4）；`updateStress` 的返回对象不得含 `derived` 键。

### 4.2 输入字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `previous` | object | 上一时刻 `state.stress`；缺字段按 `MISSING_STRESS_DATA` 降级 |
| `inputs.event` | object \| null | 单条事件；`applyEvent` 必填 |
| `event_id` / `event_type` / `occurred_at` | string / enum / string | `event_id` 匹配 `^[A-Za-z0-9_-]{8,128}$` |
| `source.*` | object | `conversation_id`、`sender_id` 为不透明标识；`relationship_tag` 见 00 §2.4；`is_mentioned` / `is_direct_question` 为布尔修正 |
| `intensity_override` | number \| null | 可选，`[-1,1]`，仅供测试/人工校正 |
| `inputs.activity.last_event_at` | string \| null | 最近任意事件时间；缺失时回退到 `previous.last_event_at`，两者都缺失才不生成 `long_silence` |
| `inputs.activity.recent_event_ids` | string[] | 模块内幂等与每日静默去重 |
| `now` | string | UTC ISO 毫秒，唯一时间来源 |

`source_key`：普通事件 `wechat:<conversation_id>:<sender_id>`；`conflict`/`admin_command` 取 `wechat:<conversation_id>:*`；`long_silence` 固定 `silence:<conversation_id>`。

### 4.3 输出（`state.stress`）

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `level` | number | `[0,1]`，`round6`，单次变化 ≤0.30 |
| `active_events` | array | ≤32 条，元素形状同 00 §3.1 |
| `remaining` | number | 有符号；`|remaining| < 0.005` 剔除 |
| `decay_profile` | enum | 五档之一 |
| `last_decay_at` / `model_version` | string / integer | 本次 `now` / 固定 `1` |
| `last_event_at` | string | 最近一次成功应用事件的 `occurred_at`；无事件时沿用 `previous.last_event_at`，初始化时等于 `created_at` |

`contributions` 只允许 `stress.level` 一个维度键，来源键固定 `decay`/`event`/`silence`，无变化写 0：

```json
{"stress.level": {"decay": -0.031, "event": 0.082, "silence": 0}}
```

### 4.4 派生输出（`derived.event_intensity`，00 §4.2 白名单）

| 键 | 类型 | 输出点 | 规则 |
| --- | --- | --- | --- |
| `derived.event_intensity` | number | **仅** `applyEvent` | 本次新事件的**最终强度**：已应用 `intensity_override`、关系倍率、`@` 加成与 `direct_question` bonus，`round6` 后落在 `[-1,1]` |

- **唯一输出点**：只有 `applyEvent` 返回 `derived`；`updateStress` 返回对象不得含 `derived` 键（交付自检项）。若 `updateStress` 也输出，02 会把旧事件的残留强度当成"本次新事件强度"，纯时间推进时 `severe` 会误判为 `true`。
- **省略条件**：`inputs.event === null`（纯时间推进）、本次没有任何新事件被应用、同 `event_id` 的重复事件（不改变任何状态）、或完整度降级时，**省略整个 `derived` 键**，不输出 `null` / `0` 占位（00 §4.2）。
- **反映最终值而非 base**：`intensity_override` 生效时取 override 后的最终强度（仍 `clamp(-1,1)`）；@ 提升、关系倍率、`direct_question` bonus 全部已计入。
- **唯一权威**：02 判定 `severe`（`>=0.7`）与装配 09 的 `inputs.event.intensity` 都只读该派生值，不得回退到原始 `event.intensity`（00 v1.7.5 §4.2）。

## 5. 算法与规则
### 5.1 基础强度与关系倍率（冻结）

| `event_type` | 基础强度 | 衰减档 | `event_type` | 基础强度 | 衰减档 |
| --- | --- | --- | --- | --- | --- |
| `group_message` | 0.02 | `fast` | `long_silence` | 0.05 | `very_slow` |
| `mention` | 0.08 | `medium` | `direct_question` | 0.06 | `medium` |
| `important_person_appear` | 0.12 | `slow` | `admin_command` | 0.00 | `none` |
| `comfort_received` | −0.10 | `medium` | `system_event` | 0.00 | `none` |
| `conflict` | 0.25 | `slow` | — | — | — |

关系倍率：`ordinary` 1.0、`important` 1.5、`intimate` 1.3、`conflict` 2.0、`admin` 0.0、`unknown` 1.0。`admin` 倍率 0.0 是管理语义：管理员指令不制造压力；强度为 0 的事件仍可记录，但不进入 `active_events`。

### 5.2 强度计算

```text
base = BASE[event_type]
if (is_mentioned && base > 0): base = max(base, 0.08)   // @ 至少按 mention 计
mult  = MULT[relationship_tag]                          // 未知 -> unknown -> 1.0
bonus = is_direct_question ? 0.02 : 0
intensity = clamp(base * mult + bonus, -1, 1)
```

- `base > 0` 才允许 @ 提升；`comfort_received`（−0.10）与 `system_event`（0）不适用，否则会把安慰翻转成正压力。
- `bonus` 在倍率之后相加、不被倍率放大；`admin` 下仍为 0。
- `intensity_override` 优先于上述计算，仍 `clamp(-1,1)`，追加 `INTENSITY_OVERRIDE`；强度 0 的事件不入 `active_events`。

### 5.3 衰减

| 档位 | `fast` | `medium` | `slow` | `very_slow` | `none` |
| --- | --- | --- | --- | --- | --- |
| τ（秒） | 120 | 900 | 3600 | 14400 | ∞ |
| 半衰期 τ·ln2 | 83.18s | 623.83s | 2495.10s | 9980.42s | 不衰减 |

```text
Δt = max(0, floor((now - last_time) / 1000))
remaining = (profile === 'none') ? intensity : intensity * exp(-Δt / τ)
remaining = round6(remaining)
```

- 逐 tick 复合：`remaining(t2) = remaining(t1) * exp(-(t2-t1)/τ)`；禁止用"原始强度 × 总时长"重算。
- `now` 早于事件时间时 `Δt = 0` 并追加 `CLOCK_REGRESSION`；`|remaining| < 0.005` 视为消失。

### 5.4 合并（300 秒窗口）

```text
a = 已有事件按 now 衰减后的 remaining
b = 新事件的 intensity
merged = clamp(max(a,b) + 0.5 * min(a,b), -1, 1)
```

| 情形 | 结果 |
| --- | --- |
| 同号 0.08 / 0.08 | 0.12（非 0.16） |
| 正负 0.25 / −0.10 | 0.20 |
| 300s / 301s | 合并 / 新建两条 |
| 合并超 1 | 裁剪到 1 + `MERGE_CLAMPED` |

合并条目：`event_id` 保留已有者，`started_at` 保留较早者，`remaining`/`intensity` 写合并值，`decay_profile` 取 `|intensity|` 较大者的档位。

### 5.5 压力目标与趋近

```text
Σremaining = Σ remaining_signed            // 负强度参与求和，用于抵扣
target     = clamp(0.15 + Σremaining, 0, 1)
alpha      = 1 - 2 ** (-dt / 1800)        // 半衰期 30 分钟
delta      = clamp((target - level) * alpha, -0.30, 0.30)
level'     = clamp(level + delta, 0, 1)
```

- 无事件时压力回到基线 0.15，不是 0；`dt = 1800` 走完差距 50%，`dt = 3600` 走完 75%。
- 裁剪时追加 `STRESS_CLAMPED`，`contributions['stress.level'].decay` 记录裁剪后的实际 `delta`；离线多步由 02 逐小时分块，每步重算 `target`。

### 5.5.1 新事件的即时反馈（applyEvent）

`updateStress` 只看旧事件，`applyEvent` 必须在**同一次推进**内让新事件立即影响 `level`，不得等到下一次调用（00 §5.4.1）：

```text
加入/合并新事件后重算：
target_after = clamp(0.15 + Σremaining_after, 0, 1)
delta_instant = (target_after - level_current) * 0.5     // 即时响应系数 0.5
level' = clamp(level_current + delta_instant, 0, 1)
单次总变化仍 ≤0.30，超出裁剪并追加 STRESS_CLAMPED
```

- `level_current` 是 `updateStress` 本步衰减后的值，不是上一步的值；
- `contributions['stress.level'].event` 记录 `level' - level_current`，可为负（安慰事件即时降压）；
- `dt = 0` 时 `updateStress` 不衰减，但 `applyEvent` 仍按 0.5 系数响应；
- 后续推进继续按 §5.5 的半衰期规则趋近新目标，不重复叠加这次即时响应。

### 5.6 `active_events` 维护

```text
1. 按 now 逐 tick 复合计算 remaining
2. 剔除 |remaining| < 0.005
3. 按 event_id 去重，保留 |remaining| 较大者
4. 按 |remaining| 降序排序，截断到 32 条并追加 EVENTS_EVICTED
5. 全部 round6，去 -0
```

排序键用绝对值，使强安慰与强冲突都优先保留，与 02 §5.2 的 `|remaining|` 降序一致。淘汰不改变历史 `level`，只影响后续 `target`。

### 5.7 `long_silence` 与幂等

生成条件（三条同时满足）：距 `max(inputs.activity.last_event_at, previous.last_event_at)` >6 小时；无未过期的非静默事件；角色本地日期当天未生成过。

- `intensity = 0.05`、`very_slow`、`source_key = silence:<conversation_id>`；`event_id = evt_silence_<YYYYMMDD>_<sha256(conversation_id).slice(0,8)>`，不拼原始 id。
- 每日上限由确定性 `event_id` + 04 幂等键 `silence_<sha256(conversation_id).slice(0,8)>_<YYYYMMDD>` 保证（幂等键不得含 `:`，见 00 §2.1）；本模块再查 `recent_event_ids` 与 `active_events` 双重去重。
- **惰性生成**：不依赖消息级订阅。任何一次 `advance`（工具调用、`/v1/tick`、每日计划）都会检查是否已超过 6 小时；因此实际精度取决于推进频率，最坏延迟等于两次推进的间隔。若宿主没有任何定时能力，`long_silence` 只能在下次工具调用时补生成，必须在 01 的宿主结论中注明。
- 生成后 `last_event_at` 更新为该事件时间；`inputs.activity` 全缺失且 `previous.last_event_at` 也缺失时，不生成并追加 `MISSING_ACTIVITY_DATA`。
- 同 `event_id` 已存在于 `active_events` 时，视为重复：**不合并、不新增、不重复计入 `Σremaining`**；`stress.level` 不变，返回原状态，`reason_codes` 含 `duplicate_event` 并追加 `DUPLICATE_EVENT_MERGED` 警告。正常流程下重复 `event_id` 应在 04 的幂等层被拦截，本分支是纵深防御。已过期后再到达按新事件处理，跨请求幂等由 04 负责。

## 6. 边界与错误
| 场景 | 处理 | 错误码 / 警告 |
| --- | --- | --- |
| `event_type` 非枚举 / `event_id` 格式非法 | 拒绝，保持原状态 | `INVALID_REQUEST` |
| `relationship_tag` 未知/缺失 | 按 `unknown`（1.0） | `UNKNOWN_RELATIONSHIP_TAG` |
| `intensity`/`level` 为 NaN/Infinity | 拒绝，不默默改 0 | `INVALID_REQUEST` |
| 重复 `event_id` 仍在列表 | 合并，不重复计数 | 成功 + `DUPLICATE_EVENT_MERGED` |
| 合并窗口内 / 外 | 合并 / 新建 | 成功 |
| `|remaining| < 0.005` | 剔除 | 成功 |
| `active_events` >32 | 截断 | 成功 + `EVENTS_EVICTED` |
| 单次 `level` 变化 >0.30 | 裁剪 | 成功 + `STRESS_CLAMPED` |
| `now` 早于 `occurred_at` | `Δt=0`，不倒退 | 成功 + `CLOCK_REGRESSION` |
| `previous` 缺字段 | 默认 `level=0.15`、空列表 | `DEGRADED` + `MISSING_STRESS_DATA` |

本模块 v1 不消费随机数。未来若引入扰动，必须用 `event:${event_id}` 派生流，不得借用 `mood`。

## 10. 禁止事项
1. 禁止写 `mood.*`、`sleep.*`、`cycle.*`、`regulation.*`；本模块只写 `stress.*`。
2. 禁止改动 §5.1 的基础强度、关系倍率与 §5.3 的 τ。
3. 禁止用关键词、正文或发送者昵称推断 `relationship_tag`。
4. 禁止把同源事件简单相加，必须走 5.4 的 `max + 0.5×min`。
5. 禁止让压力无限累积；必须回到 0.15 基线并受 0.30 单步上限约束。
6. 禁止保存消息正文、原始 wxid 或把 `conversation_id` 拼进 `event_id`。
7. 禁止读系统时间或 `Math.random()`；不得新增状态字段，需要时走契约变更。

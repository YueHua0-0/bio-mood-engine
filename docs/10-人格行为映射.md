## 1. 背景与目标
情绪引擎回答"角色现在是什么状态"，本模块回答"这种状态应表现成什么倾向"。输出是 `behavior_context`：一组**约束与倾向**，交给宿主与 DSH 组织语言，不是可直接发送的台词。引擎不生成句子，只给出"多大概率回、大概多快回、话多话少、亲近还是克制、睡前约束是什么"。

本模块的全部数值、阈值与文案均为**虚构角色状态模拟**，不是人体医学模型，不用于诊断、治疗或现实健康预测；不得据此推断真实心理或生理状况。

### 1.1 关键约束（摘自 00，不得改动）
- 输出字段与枚举严格等于 00 §12.4 的 `behavior_context` 与 §2.8 的行为枚举，不新增字段与枚举值。
- 所有 `[0,1]` 数值 `round6`，禁止 `NaN` / `Infinity` / `-0`。
- 纯函数：不读系统时间、不访问网络/存储、不使用 `Math.random()`；本模块**不消费随机数**，天然确定。
- `hard_rule_precedence` 恒为 `true`（不变量 I8）：角色卡与用户硬规则永远高于模拟倾向。
- 只读 `mood.*` / `sleep.*` / `stress.level`，不写任何状态字段。

## 2. 范围与非目标
**范围**：回避倾向、回复概率、社交主动性、安抚需求四个连续量；四档延迟区间与整数秒归一；`verbosity_bias` 与 `affection_expression` 三档判定及滞回；`sleep_constraint` 六态覆盖；`behavior_notes` 固定文案表、优先级挑选、长度与合规校验；`reason_codes` 稳定排序；上下文注入长度保护。

**非目标**：不生成自然语言台词、不做角色扮演、不写角色卡；不判断消息是否需要发送（11）、不计算情绪（09）、不计算睡眠（06）；不持久化 `behavior_context`（它是派生输出，不进入 `CharacterState`）；不新增状态字段。

## 4. 输入 / 输出

`rng` 仅为对齐 00 §4.1 签名保留，本模块**必须不调用**它，也不得转发给其他模块。

### 4.2 输入字段
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `previous` | object \| null | 上一次的 `{verbosity_bias, affection_expression}`，仅用于滞回；由协调器经 `previousBehaviorContext` 传入（02 §5.4），首次调用为 `null`。**只读取这两个键，其余字段忽略**——调用方可传完整 `behavior_context`，也可只传这两键 |

事件正文、会话标识、`event_type` 不进入本模块；行为倾向只随状态变化，不随"说了什么"变化。

| 字段 | 类型 | 规则 |
| --- | --- | --- |

## 5. 算法与规则

### 5.1 回避倾向
```text
avoidance = clamp(0.55 - 0.50*social_drive + 0.40*stress
                        + 0.30*sensitivity - 0.30*stability, 0, 1)
```
输入先 `clamp(0,1)` 再代入（上游越界追加 `INPUT_CLAMPED`）。语义：社交意愿越低、压力与敏感越高、稳定度越低，越倾向回避。

### 5.2 回复概率
```text
reply = clamp(0.30 + 0.40*social_drive + 0.25*(1-avoidance) + 0.20*energy
                   - 0.35*sleepiness - 0.25*sleep_debt, 0, 1)
```
`avoidance` 取 §5.1 **round6 前**的值参与计算，仅对最终输出 `round6`，避免二次舍入放大误差。单调性：`social_drive` 升高时 `reply` 不得下降。

### 5.3 延迟区间
| `reply_likelihood` | 区间（秒） | 语义 |
| --- | --- | --- |
| `r ≥ 0.70` | `[10, 120]` | 近乎即时 |
| `0.40 ≤ r < 0.70` | `[60, 600]` | 正常节奏 |
| `0.20 ≤ r < 0.40` | `[300, 1800]` | 明显延后 |
| `r < 0.20` | `[1200, 7200]` | 很可能不回 |

比较前先 `round6(r)`，阈值比较用 `1e-9` 容差，避免 `0.6999999` 落错档；恰等于阈值时计入较高一档。端点先 `round6` 再取整数秒。模块**只给区间、不采样**，具体秒数由宿主在区间内决定，保证同输入输出完全一致。

### 5.4 话量倾向（±0.05 滞回）
| 当前档 | 保持条件 | 切换条件 |
| --- | --- | --- |
| `low` | `energy < 0.40` 或 `sleepiness > 0.55` | 两者都不满足 → 重新判定 |
| `high` | `energy ≥ 0.57` 且 `social_drive ≥ 0.53` | 任一不满足 → 重新判定 |
| 其他 | 按基础阈值 | `energy ≥ 0.62 且 social_drive ≥ 0.58` → `high`；`energy < 0.35 或 sleepiness > 0.60` → `low`；否则 `normal` |

判定顺序固定为 **先 `low`、再 `high`、最后 `normal`**，避免滞回区间内两档同时成立时结果不确定。上一档缺失时直接走基础阈值并追加 `HYSTERESIS_RESET`。

进入阈值与保持阈值差 0.05，与"±0.05 滞回"一致。09 的 home（`energy=0.60`、`social_drive=0.55`）不满足 `high` 进入条件（`0.62/0.58`）也不满足 `low`，稳态即 `normal`（v1.7.9，W5-4）。

滞回输入的实际生命周期（与 02 §5.4、13 §4.4 一致）：协调器在同一次 `advance` 的多个 chunk 之间传入上一 chunk 的 `behavior_context`，滞回因此生效；`behavior_context` 不持久化，**跨 `advance` 一律无记忆**（每次工具调用、每次进程重启后的首个 chunk 都是 `previous=null`）。测试预期按此编写，不得断言"跨 tick 保持上一档"。

### 5.5 亲密表达（±0.05 滞回）
| 当前档 | 保持条件 | 切换条件 |
| --- | --- | --- |
| `reserved` | `closeness_need < 0.40` 或 `stress > 0.65` | 两者都不满足 → 重新判定 |
| `warm` | `closeness_need ≥ 0.65` 且 `stress < 0.55` | 任一不满足 → 重新判定 |
| 其他 | 按基础阈值 | `closeness_need ≥ 0.70 且 stress < 0.50` → `warm`；`closeness_need < 0.35 或 stress > 0.70` → `reserved`；否则 `normal` |

判定顺序固定为 **先 `reserved`、再 `warm`**：高压力下宁可克制，不允许因亲近需求高而输出 `warm`。

### 5.6 睡眠约束
| `sleep.state` | 附加条件 | `should_reply` | `tone` | `max_reply_length` |
| --- | --- | --- | --- | --- |
| `sleeping` | — | `false` | `sleepy` | `short` |
| `waking_up` | — | `true` | `waking` | `normal` |
| `awake` / `sleepy` / `trying_to_sleep` / `interrupted` | `sleepiness > 0.60` | `true` | `sleepy` | `normal` |
| `awake` / `sleepy` / `trying_to_sleep` / `interrupted` | `sleepiness ≤ 0.60` | `true` | `none` | `normal` |

`sleeping` 的约束**优先于一切行为倾向**：即使 `reply_likelihood = 1.0`，`should_reply` 也必须为 `false`、`max_reply_length` 必须为 `short`。表中未覆盖的字段取默认分支值，不得自行扩展枚举。

### 5.7 主动性与安抚需求
`social_initiative = clamp(0.50*social_drive + 0.30*energy - 0.40*avoidance, 0, 1)`
`need_for_reassurance = clamp(0.60*closeness_need + 0.40*sensitivity - 0.30*stability, 0, 1)`
两者均为倾向强度，不是"要不要发消息"的开关；是否发起由 11 与宿主决定。

### 5.8 行为提示文案（固定表 ≥11 条）
| 优先级 | 条件 | 文案（≤40 字符，纯定性） |
| --- | --- | --- |
| 1 | `sleep.state === 'sleeping'` | 当前处于睡眠模拟状态，倾向延迟回应 |
| 2 | `sleep.state === 'waking_up'` | 刚醒来，回应节奏偏慢 |
| 3 | `sleepiness > 0.75` | 困倦明显，表达应简短 |
| 4 | `sleep_debt ≥ 0.50` | 近期休息不足，耐心偏低 |
| 5 | `physical_comfort < 0.45` | 身体状态不太舒服 |
| 6 | `stress ≥ 0.55` | 压力偏高，语气偏紧 |
| 7 | `energy < 0.35` | 精力不足，回复偏短 |
| 7 | `energy ≥ 0.70 且 social_drive ≥ 0.60` | 精力充沛，愿意多聊 |
| 8 | `avoidance ≥ 0.60` | 回避倾向上升，先观察再回应 |
| 9 | `closeness_need ≥ 0.70` | 希望被回应与陪伴 |
| 10 | `affection_expression === 'reserved'` | 保持礼貌距离 |
| 11 | 兜底 | 语气自然，跟随当前情境 |

按优先级自上而下取前 3 条命中项。文案表是**唯一合法来源**：不得即席拼接，不得出现数字、公式符号、维度名，不得出现"诊断 / 激素 / 医学"字样；它是给宿主的提示，不是发给用户的句子。禁用词只约束**输出到 `behavior_notes` 的文本**，文档说明与代码注释中的同名说明不受限（验收检索命中注释时按白名单确认）。

第 7 条文案仅在 `energy ≥ 0.70 且 social_drive ≥ 0.60` 时出现，与 `verbosity_bias='high'` 的进入阈值（§5.4，`0.62/0.58`）**不要求重合**——文案是"提示"，`high` 只表示"偏多话"，不必"精力充沛"（v1.7.9）。

### 5.9 优先级与注入长度
| 级别 | 来源 | 引擎可否覆盖 |
| --- | --- | --- |
| 1 | 系统安全（平台安全策略、合规要求） | 否 |
| 2 | 用户硬规则（如"凌晨不要主动发消息"） | 否 |
| 3 | 角色卡与群聊规则 | 否 |
| 4 | 关系与语境（`relationship_tag`、会话性质） | 部分 |
| 5 | 引擎倾向（本模块输出） | — |
| 6 | 随机细节（语气小变化） | 是 |

`hard_rule_precedence` 恒为 `true`，表示 1–3 级永远高于第 5 级，且不得随任何输入变为 `false`。注入长度取 `JSON.stringify(behavior_context)` 的字符数（UTF-16），必须 ≤800；超限按 **删 `behavior_notes`（从末条起）→ 删 `reason_codes`（从末条起）→ 追加 `CONTEXT_TRUNCATED`** 处理；仅当数值与枚举字段本身仍超限时抛 `MODULE_FAILED`（该情形只可能由实现错误导致）。

### 5.10 原因码（≤16，顺序固定）
`sleeping` → `waking_up` → `sleepiness_high` → `sleep_debt_high` → `stress_high` → `energy_low` → `energy_high` → `social_drive_low` → `social_drive_high` → `avoidance_high` → `reply_likely` → `reply_unlikely` → `closeness_high` → `reserved_tone` → `warm_tone` → `context_truncated`；按此顺序去重输出。

### 5.11 精度与确定性
所有数值输出 `round6`，`-0` 归一为 `0`；同一 `inputs` + 同一 `previous` 必得深度相等结果，无随机、无时间依赖、无缓存副作用。

## 6. 边界与错误
| 场景 | 处理 | 错误码 / 警告 |
| --- | --- | --- |
| 输入数值 `NaN` / `Infinity` | 拒绝本次计算，不输出上下文 | `INVALID_REQUEST` |
| 输入数值越界（如 `energy = 1.2`） | 先钳制 `[0,1]` | 成功 + `INPUT_CLAMPED` |
| `mood` 缺维度 / `stress.level` 缺失 | 用 09 的 home 值 / 取 `0.15` | `DEGRADED` + `MISSING_MOOD_DATA` / `MISSING_STRESS_DATA` |
| `sleep` 缺失 / `state` 非枚举 | 契约默认值 / 按 `awake` 处理 | `DEGRADED` + `MISSING_SLEEP_DATA` / `UNKNOWN_SLEEP_STATE` |
| `previous` 缺失或档位非法 | 走基础阈值判定 | `HYSTERESIS_RESET` |
| 文案含数字 / 禁用词 | 该条回退到兜底文案 | `INVALID_BEHAVIOR_NOTE` |
| `behavior_notes` >3 条或某条 >40 字符 | 截断到前 3 条 / 丢弃超长项 | `NOTES_TRUNCATED` |
| 上下文 >800 字符 | 按 §5.9 顺序截断 | `CONTEXT_TRUNCATED` |

## 10. 禁止事项
1. 禁止把数值直接翻译成固定台词（"回复概率 0.18"这类表达一律禁止），只允许 §5.8 的定性文案。
2. 禁止出现"诊断 / 激素 / 医学 / 治疗"字样，不得把模拟量描述为真实健康指标。
3. 禁止改动 §5.1–§5.7 的公式系数与 §5.3 的四档区间端点。
4. 禁止改变滞回判定顺序（必须 `low` / `reserved` 优先）。
5. 禁止让 `hard_rule_precedence` 变为 `false`，或以任何方式让引擎倾向覆盖系统安全与用户硬规则。
6. 禁止读写 `CharacterState` 任意字段，禁止新增状态字段或枚举值。
7. 禁止使用随机数、系统时间、网络或存储；禁止 `behavior_notes` 超 3 条 / 40 字符 / 800 字符总长。
8. 禁止修改 `00`–`09`；需要新字段时走契约变更流程。

## 1. 背景与目标

周期模块只负责一件可验证的事：**给定锚点、周期序号和当前时间，算出角色处于哪个模拟阶段，以及该阶段对情绪的固定影响量**。它不做医学推断，不预测现实生理事件，也不把阶段与某一种固定情绪绑定（同一阶段在不同角色、不同调节与压力输入下情绪可以不同）。本模块的阶段、长度、置信度均为**虚构角色状态模拟**，不是人体医学模型，不用于诊断、治疗或现实健康预测；阶段名保留 `_like` 后缀正是为了标明这一点。

### 1.1 关键约束（摘自 00，不得改动）

- 阶段枚举只有 `menstrual_like` / `follicular_like` / `ovulatory_like` / `luteal_like`；`cycle_day` 1 起算，范围 `[1, cycle_length_days]`；`phase_progress ∈ [0,1)`；
- 周期只写 `cycle.*`，只输出原始阶段向量，由 09 计算 `mood` 的 `cycle` 贡献；**不得**写 `stress.*`、`sleep.*`、`regulation.*`；
- 时间只依赖 `now` 与 `anchor_at` 的 UTC 差，禁止用本地时区推算周期；随机只来自 `rng`。

---

## 2. 范围与非目标

**范围**

- 周期长度采样（基准、标准差、区间钳制、来源标记）；
- 阶段判定、阶段进度、阶段影响向量与边界过渡；
- 跨周期与跨多周期的 O(1) 推进；置信度演进与人工校正；`contributions` 输出。

**非目标**：不负责情绪合成（09）与调节特征（08）；不做症状、受孕窗口、医学预测或现实日期推荐。

## 5. 算法与规则

### 5.1 周期长度采样

每个周期开始时采样一次，流标签 `cycle:${cycle_index}`，**只消耗 1 次 `nextNormal()`**：

```text
z_len  = rng.nextNormal()
L      = clamp(28.4 + 1.2 * z_len, 24, 34)
```

锚点抖动 `jitter` 只在初始化时由调用方用独立流 `cycle:init` 采样一次，之后每周期沿用，`advanceCycleDays` 不再消耗 `z_jit`（避免每周期浪费一次随机数）。

首次初始化且未采样时用 `28.4` 且 `source='default'`；采样后写 `source='sampled'`；人工指定长度写 `source='manual'` 且不消耗随机数。随机只影响长度与锚点抖动，**不得**影响阶段向量或情绪。

`previous.cycle_length_source === 'default'` 时，首次 `updateCycle` **必须**消耗 1 次 `nextNormal()` 采样并写 `source='sampled'`，**不得**跳过采样直接沿用 28.4；缺 `rng` 时抛 `MODULE_FAILED`（`details.reason='cycle_source_unresolved'`）。02 在 `advance` 末尾断言不得残留 `default`（00 v1.7.6 §3.2）。

### 5.2 阶段边界

`p = (cycle_day - 1) / cycle_length_days`，边界按比例固定：

| 阶段 | 起点 `p` | 终点 `p` | `cycle_day`（L=28.4） |
| --- | --- | --- | --- |
| `menstrual_like` | 0 | 0.18 | 1.000 – 6.112 |
| `follicular_like` | 0.18 | 0.44 | 6.112 – 13.496 |
| `ovulatory_like` | 0.44 | 0.53 | 13.496 – 16.052 |
| `luteal_like` | 0.53 | 1.00 | 16.052 – 29.400 |

判定左闭右开，容差 `1e-9`：`[0,0.18)` / `[0.18,0.44)` / `[0.44,0.53)` / `[0.53,1.0)`。`phase_progress = (p - 起点) / (终点 - 起点)`，截断到 `[0,1)`，跨周期归零。

### 5.3 阶段影响向量与过渡

#### 5.3.1 九维阶段矩阵（v2，2026-11 周期扩展）

**旧四维的 physical_comfort 语义调整**：明确表示"不包含疼痛负荷的身体舒适度"，疼痛由独立的 `pain_load` 表达，避免重复计算。因此 menstrual_like 的 physical_comfort 从 −0.10 改为 −0.04，luteal_like 从 −0.07 改为 −0.05。energy / sensitivity / social_drive 三个旧维度的阶段值**完全沿用旧值**。

**新五维**：pain_load、anxiety_delta、irritability_delta、positive_affect_delta、intimacy_need_delta。

| 阶段 | physical_comfort | energy | sensitivity | social_drive | pain_load | anxiety_delta | irritability_delta | positive_affect_delta | intimacy_need_delta |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `menstrual_like` | −0.04 | −0.06 | +0.05 | −0.03 | 0.60 | +0.15 | +0.20 | −0.15 | −0.10 |
| `follicular_like` | +0.05 | +0.06 | −0.02 | +0.05 | 0.05 | −0.10 | −0.10 | +0.20 | +0.05 |
| `ovulatory_like` | +0.03 | +0.04 | +0.01 | +0.06 | 0.05 | −0.05 | −0.05 | +0.25 | +0.35 |
| `luteal_like` | −0.05 | −0.04 | +0.07 | −0.02 | 0.35 | +0.12 | +0.18 | −0.10 | −0.05 |

> 上述新五维为首轮设计初值，属于待仿真校准参数，不应被描述为医学事实。

#### 5.3.2 profile 参数调制（四个扁平设置，范围 [0,1.5]，默认 1.0）

四个设置经 D1 裁决落在**插件设置**，为四个扁平键，经 `engineConfigOf(state, settings)` 组装为 `config.cycle.profile`（类型为 `{cyclePainSensitivity, cycleLutealSensitivity, cycleMoodVariability, cycleIntimacyVariability}`）。本模块消费 profile：

1. `cyclePainSensitivity`：只乘 **pain_load** 维度（所有阶段）。公式 `pain_load × clamp(profile.cyclePainSensitivity, 0, 1.5)`。
2. `cycleLutealSensitivity`：只乘 **黄体期权重对应的 anxiety_delta 和 irritability_delta** 分量（menstrual_like → 1.0；follicular_like → 0.3；ovulatory_like → 0.1；luteal_like → 1.0）。注意：不得乘以混合后的整体结果（D2）。
3. `cycleMoodVariability`：只乘 **anxiety_delta、irritability_delta、positive_affect_delta**。
4. `cycleIntimacyVariability`：只乘 **intimacy_need_delta**。

profile 只影响五维新维度的最终输出，旧四维（physical_comfort / energy / sensitivity / social_drive）**不乘 profile**，以保证 P-08-01 既有 08 通道的叠加上限仍可精确计算。

#### 5.3.3 阶段权重函数（给 cycleLutealSensitivity 用）

```text
function lutealWeight(phase):
  menstrual_like -> 1.0
  follicular_like -> 0.3
  ovulatory_like -> 0.1
  luteal_like -> 1.0
```

#### 5.3.4 向量输出格式

本模块只输出**原始阶段向量**（上表 + profile 调制后，含交叉淡入结果），**不写 `state.cycle`、不直接写 `mood.*`**。输出路径固定为 `ModuleResult.derived.phase_impact = {physical_comfort, energy, sensitivity, social_drive, pain_load, anxiety_delta, irritability_delta, positive_affect_delta, intimacy_need_delta}`（00 §4.2）；协调器按流水线顺序把它作为 `inputs.cycle.phase_vector` 传给 09，`derived` 不持久化、不进 `evlog`。

新五维在 05 内完成限幅 `clamp([-1,1])`（pain_load 和 intimacy_need_delta 等边界差异见 §5.3.5）；09 不再重复限幅。

**降级时不输出 `derived`**（00 §4.2）：周期数据缺失或 `previous` 缺字段时，本模块**省略 `derived` 键**（不得输出全 0 占位），只把自己的 `MISSING_CYCLE_DATA` 追加到 `warnings`；09 收不到 `phase_vector` 时按"旧四维 + 五个新维度全 0"处理（09 §4.2 / §5.2），两处追加的同一警告码由 `diagnostics.warnings` 合并去重（02 §5.5）。

`contributions['mood.<dim>'].cycle` 由 09 统一计算；05 的 `contributions` 只记录自身状态变化（如 `cycle.phase_progress`、`cycle.confidence`），不得出现 `mood.` 或 `stress.` 前缀的键，也不得用 `contributions['cycle.phase_impact']` 之类的变通路径。连续性约束：旧四维（physical_comfort / energy / sensitivity / social_drive）相邻两天原始向量任一维差 ≤0.15，经 09 的惯性系数与 00 §7.3 的单次 0.06 上限后，单次推进的情绪变化必然 ≤0.06。新五维的相邻两天差上限待 C6 仿真后登记在 §8 测试要求。

#### 5.3.5 边界条件

- 除 pain_load（值域 `[0, 1]` 非对称）外，其余八维统一 `clamp([-1, 1])`。
- profile 设置超出 `[0, 1.5]` 范围时，**只回退默认 1.0**，按非法值种类去重记录一次 `FASTCFG_INVALID`（不在 05 内处理，由配置层统一处理，见 13 §4.4）。
- HTTP 本轮固定四项默认 1.0，不开放 profile 入参（D2 裁决）。

### 5.4 跨周期推进（按周期循环，上限 64 次）

周期长度**每周期独立采样**，因此跨周期必须逐周期推进；只允许"按周期循环"，禁止"按天循环"（I12）。180 天最多跨 8 个周期，成本可忽略。

**回绕容差（P-14-04，裁决 A）**：`cycle.cycle_day` 以 6 位小数持久化，同一次推进内 `predict` 与 `commit` 轮会读到 `±1e-6` 天的舍入噪声。实现允许 **`±1e-5` 天**的负向容差——`deltaDays ∈ (-1e-5, 0]` 视为 0（本轮不推进），超出 `-1e-5` 仍按「`cycle_day` 超前于实际时间」报 `MODULE_FAILED`（`lib/modules/cycle/index.mjs` 的 `DAY_EPSILON`）。容差只吸收浮点噪声，不掩盖真实的锚点错位。

```text
MAX_CYCLE_STEPS = 64
remaining = L - (cycle_day - 1)
if (deltaDays < remaining) { cycle_day += deltaDays; 重算 phase; return }

d = deltaDays - remaining
anchorMs += remaining * 86400_000
cycle_index += 1
cycle_day = 1
loops = 0

while (d >= 0 && loops < MAX_CYCLE_STEPS) {
  L = sampleLength(cycle_index)          // 流 cycle:${cycle_index}，每周期 1 次
  if (d < L) { cycle_day = 1 + d; break }
  d -= L
  anchorMs += L * 86400_000
  cycle_index += 1
  loops += 1
}

if (loops === MAX_CYCLE_STEPS && d >= 0) {   // >64 个周期，约 4 年以上
  k = floor(d / 28.4)                        // 期望长度粗推进
  cycle_index += k
  cycle_day = 1 + (d - k * 28.4)
  warnings.push('CYCLE_COARSE_ROLL')
}
anchor_at = toIso(anchorMs)                  // 当前周期起点；单次锚点抖动 ≤0.3 天由调用方初始化时注入
```

规则：

- 每进入一个新周期调用一次 `sampleLength(cycle_index)`，流标签带周期序号，保证"跳过若干周期"与"逐周期推进"结果一致；
- `MAX_CYCLE_STEPS = 64` 是硬上限；超出后按期望长度 28.4 天粗推进并告警，不再逐周期采样；
- 任何情况下不允许 `for (day...)` 或按小时循环（单次调用最多 64 次迭代）；
- 180 天离线必须与按周期逐步推进的 `cycle_index` 完全一致（不是"误差 ≤1"）；
- `phase_progress` 计算后必须 `min(progress, 0.999999)`，确保落在 `[0,1)`。

### 5.5 置信度与人工校正

| 场景 | 变化 | 上下限 |
| --- | --- | --- |
| 初始 | `0.40` | — |
| 每完成一个采样周期 | `+0.04` | 上限 `0.90` |
| 人工校正 | 直接置 `0.95` | — |
| 人工校正后每完成一个周期 | `-0.01` | 下限 `0.50` |

`cycle_length_source === 'manual'` 时只走衰减分支，其余只走增长分支，不叠加；`confidence` 变化不产生 `contributions`。人工校正写 `anchor_at`、`cycle_length_days`、`source='manual'`、`confidence=0.95`，立即重算 `cycle_day` 与 `phase`，追加 `cycle_manual_correction`；`cycle_index` 不回退、不重置随机流；长度不在 `[20,45]` 或锚点晚于 `now` → `INVALID_REQUEST`。

`contributions` 只允许 `cycle.` 前缀键（如 `cycle.phase_progress`、`cycle.confidence`）；`mood.*` 由 09 统一写入，05 不得写 `mood`、`stress`、`sleep`、`regulation`。

## 6. 边界与错误

| 场景 | 处理 | 错误码 |
| --- | --- | --- |
| 配置 `base` 越界、`min ≥ max`、`sd` 越界 | 拒绝启动 | `INVALID_REQUEST` |
| 人工长度越界 / 锚点在未来 | 拒绝并保持原状态 | `INVALID_REQUEST` |
| `cycle_day ≤ 0`、`NaN` 或 `now` 早于 `anchor_at` | 视为损坏 | `MODULE_FAILED` |
| `phase_progress` 恰为 1 | 截断为 `0.999999` | 成功 |
| 正常跨多周期（≤64 个） | 逐周期采样并累加 `cycle_index`，不告警 | 成功 |
| 跨 >64 个周期 | 按期望长度粗推进 + `CYCLE_COARSE_ROLL` | 成功 + 警告 |
| `previous` 缺字段 | 契约默认值；**省略 `derived.phase_impact`**；本模块**必须追加** `MISSING_CYCLE_DATA`（与 §5.3 一致，09 也会追加，合并去重） | `DEGRADED` + `MISSING_CYCLE_DATA` |

## 10. 禁止事项

1. 禁止按天循环推进周期，必须用除法 + 取模的常数时间算法。
2. 禁止改动 §5.2 的阶段比例与 §5.3 的影响向量数值。
3. 禁止让随机数直接影响情绪维度（随机只作用于长度与锚点抖动）。
4. 禁止写 `stress.*`、`sleep.*`、`regulation.*` 或 `mood` 的其他维度。
5. 禁止用本地时区、日历天或 `new Date()` 计算周期，只允许 UTC 毫秒差。
6. 禁止把阶段解释为医学结论，或输出症状、受孕、诊断类描述；禁止用 `cycle_day` 为 0 起算或右闭区间。
7. 禁止修改 `00`；需要新阶段或新字段时走契约变更流程。

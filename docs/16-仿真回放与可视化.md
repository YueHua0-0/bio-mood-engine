## 1. 背景与目标

单个模块的测试通过，不代表组合后的角色状态"像那么回事"。可能出现每维都合法、组合却不合理的状态：

```text
睡眠：正常 / 压力：0.95 / 稳定性：0.95 / 社交意愿：0.05 / 亲近需求：0.95 / 回复概率：0.95
```

本模块是一个**离线工具**：输入固定事件序列与种子，完整推进引擎，输出可读的状态曲线、异常报告与确定性指纹。它不进入插件包，不参与生产请求。

目标：

1. 用同一份脚本可反复复现任意一天的完整状态轨迹；
2. 能对比两次运行（改参数、改版本）的差异；
3. 自动发现越界、振荡、长期贴边、异常恢复等"组合问题"；
4. 输出人类可读的 SVG 曲线（单文件 HTML），便于评审。

### 1.1 非目标

- 不替代单元测试与契约测试（属于 14）；
- 不生成"角色台词"或评价人设好坏；
- 不连接真实微信、不读取真实聊天记录；
- 不修改引擎任何模块，只调用公共接口。

## 3. 输入 / 输出

### 3.1 输入：仿真脚本 `scenario.json`

```json
{
  "scenario_id": "quiet_week",
  "description": "平静一周，仅普通群消息与被 @",
  "character_id": "whale_character",
  "timezone": "Asia/Shanghai",
  "master_seed_hex": "000102030405060708090a0b0c0d0e0f",
  "start_at": "2026-11-01T00:00:00.000Z",
  "end_at": "2026-11-08T00:00:00.000Z",
  "step_seconds": 3600,
  "config_overrides": {},
  "events": [
    {
      "at": "2026-11-01T09:15:00.000Z",
      "event_id": "evt_sim_0001",
      "event_type": "group_message",
      "conversation_id": "group_sim",
      "sender_id": "sim_sender_a",
      "relationship_tag": "ordinary",
      "is_mentioned": false,
      "is_direct_question": false
    }
  ],
  "assertions": {
    "max_abs_delta_per_step": 0.15,
    "mean_ranges": {"mood.energy": [0.2, 0.8]},
    "no_edge_run_hours": 72
  }
}
```

约束：

- `events` 按 `at` 升序，允许同一时刻多条；最多 20,000 条；
- `step_seconds` 必须是 3600 的整数倍（即 3600 必须整除 `step_seconds`，只允许 3600/7200/…），默认 3600（与生产 1 小时粒度一致）；
- `master_seed_hex` 必须来自测试白名单 `tests/fixtures/seeds.json`（文件内为 32 位纯十六进制，供测试专用），否则拒绝；不得使用任何 `test_` 之类的非十六进制前缀（00 §3.2 要求 32 位十六进制）；
- 不允许 `text`、`wxid` 等字段；出现即 `INVALID_REQUEST`。

### 3.2 输出

| 文件 | 内容 |
| --- | --- |
| `<scenario>.trace.jsonl` | 每步一行：`{t, state_version, sleep.state, sleepiness, sleep_debt, stress.level, mood.*, regulation.*, delivery?: {policy, coalesced_merged?}}` |
| `<scenario>.report.json` | 汇总统计、异常列表、断言结果、`stateFingerprint` |
| `<scenario>.html` | 单文件可视化：6 张 SVG 曲线 + 事件标注 + 异常高亮，无外部依赖 |
| `<scenario>.contrib.json` | 关键节点的贡献分解（用于解释"为什么变成当前状态"） |

`delivery` 字段（v1.7.9，W6-4）：仿真每步记录 `advance` 返回的 `delivery`，只写入 `policy` 与可选的 `coalesced_merged`（取自 `delivery.coalesced_into.merged_count`，无合并时**整键省略**，不写 0 也不写 null）。16 只读不消费——不实现队列、不重试、不判断是否交付。SIM05（睡眠中连续 @）需在报告中展示"折叠了几条"。

HTML 必须满足：无 CDN、无外链字体、无脚本请求；直接双击可看；颜色区分周期/睡眠/压力/情绪/调节；横轴为本地时间。

## 4. 算法与规则

### 4.1 推进循环

```text
state = createDefaultState(...)
t = start_at
for each step until end_at:
  eventsThisStep = 取出 [t, t+step) 内的事件（可能多条）
  rng = RandomProvider.fromPersisted({ random: state.random, character_id })
  for e of eventsThisStep:
      r = await advance({ state, event: e, now: e.at, rngProvider: rng, config })
      state = r.state
  // 无论本步是否有事件，都必须推进到步末，避免时间跳跃
  r = await advance({ state, event: null, now: toIso(t + step), rngProvider: rng, config })
  state = r.state
  记录 trace 行
  t += step
```

- **必须 `await`** 且严格串行：禁止 `Promise.all` 并发推进、禁止用同步长循环阻塞事件循环（单步超过 5 s 必须 `await new Promise(setImmediate)` 让出）；
- 每步用 `RandomProvider.fromPersisted(...)` 从 `state.random` 恢复，推进后由 `advance` 写回，保证与生产一致；
- `advance` 抛错时**丢弃当前 `rng`**，下一步重新 `fromPersisted`；不得在失败后复用已消费的 provider（03 §5.7 / 00 §11.4）；
- 不得直接调用单个模块，必须走协调器，否则测不到流水线顺序与上限裁剪；
- 事件时间与步长不一致时，以事件时间为 `now` 先推进（等价于生产中的即时事件）。

### 4.2 异常检测（报告必须逐项给出）

| 编号 | 检测 | 判定 |
| --- | --- | --- |
| A1 | 数值越界 | 任一 `[0,1]` 字段越界或 `NaN` |
| A2 | 单步突变 | `|Δ| > 0.12`（高严重度）或 `> 0.06`（普通）；`|Δ| > 0.15` 视为实现错误（对应 09 的 `MODULE_FAILED` 断言） |
| A3 | 长期贴边 | 连续 72 小时 `>0.98` 或 `<0.02` |
| A4 | 振荡 | 12 小时内同维符号翻转 ≥6 次且幅度 >0.05 |
| A5 | 恢复失败 | 事件结束 24 小时后仍偏离 home >0.30 |
| A6 | 睡眠异常 | 连续清醒 >36 小时，或单次睡眠 >14 小时 |
| A7 | 压力不衰减 | 无事件 6 小时后 `stress.level` 下降 <0.02 |
| A8 | 贡献不平 | `Σcontributions` 与 `next-prev` 差 >1e-6 |
| A9 | 确定性 | 两次运行 `stateFingerprint` 不同 |
| A10 | 组合矛盾 | `sleepiness >0.85` 且 `reply_likelihood >0.7`；`stress >0.8` 且 `stability >0.9` 且 `energy >0.8` |

A10 只报警不改值，用于人工评审"组合是否自然"。

### 4.3 确定性

- 同一 `scenario.json` 连续运行两次，四个输出文件的 `trace` 与 `report.fingerprint` 必须逐字节一致（HTML 除时间戳外一致）；
- 关闭时间戳与随机排序后计算 `sha256`；报告中写入 `engine_version`、`schema_version`、`algorithm_version`；
- 跨 Node 20/22 运行结果必须一致（BigInt 与 `Intl` 行为已固定）。

### 4.4 差异对比

`node tools/sim/diff.mjs a.trace.jsonl b.trace.jsonl` 输出：

- 首次分叉的 `t` 与字段；
- 最大差值、平均差值、差值持续时长；
- 是否仅由 `config_overrides` 引起（报告中列出差异配置）。

### 4.5 性能

| 场景 | 上限 |
| --- | --- |
| 7 天 × 1 小时（168 步） | < 1 s |
| 90 天 × 1 小时（2160 步） | < 2 s |
| 365 天 × 1 小时（8760 步） | < 8 s |
| 20,000 条事件 | < 30 s |

超限视为性能回归，必须在报告中标注。

## 5. 边界与错误

| 场景 | 处理 | 错误码 |
| --- | --- | --- |
| 脚本缺 `start_at` / 时间格式错误 | 拒绝 | `INVALID_TIME` |
| `end_at ≤ start_at` | 拒绝 | `INVALID_REQUEST` |
| 事件时间超出区间 | 拒绝并指出索引 | `INVALID_REQUEST` |
| 事件含 `text` / `wxid` | 拒绝 | `INVALID_REQUEST` |
| 脚本种子不在测试白名单 | 拒绝并提示 | `INVALID_REQUEST` |
| 20,000 条以上事件 | 拒绝 | `PAYLOAD_TOO_LARGE` |
| 运行中断 | 保留已写 trace，报告标记 `incomplete` | — |
| 两次运行指纹不同 | 报告 `A9`，退出码 2 | — |

退出码：`0` 全部通过；`1` 有断言失败；`2` 确定性失败；`3` 输入非法。

## 9. 禁止事项

1. 禁止把仿真工具打包进插件 ZIP。
2. 禁止读取真实聊天记录或生产存储；只能使用脚本内构造的事件。
3. 禁止使用真实角色的 `master_seed_hex`；只能使用 `tests/fixtures/seeds.json` 中的测试种子。
4. 禁止为了让曲线"好看"而修改引擎参数或后处理 trace。
5. 禁止在 HTML 中引入 CDN、外部字体、远程脚本。
6. 禁止把"断言通过"当成"人设合理"；组合矛盾 A10 必须人工复核。
7. 禁止跳过协调器直接调用模块，否则测不到流水线与裁剪。

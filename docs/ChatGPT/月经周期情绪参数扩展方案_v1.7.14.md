## 1. 设计目标与边界

### 1.1 目标

在现有周期阶段影响机制上增加更细致的模拟参数，使角色状态能够表达以下趋势：

-   经期：疼痛负荷升高，身体舒适度和精力受到影响，情绪稳定性可能下降。
-   卵泡期：整体状态趋于轻松，积极情绪倾向增强。
-   排卵期：积极情绪和亲密需求倾向可能增强。
-   黄体期：焦虑和易激惹倾向可能增强，情绪稳定性可能下降。

这些是**虚构角色状态模拟参数**，不是医学模型，不用于预测真实个体的月经、诊断疾病或给出医疗建议。参数只表达倾向，不应决定角色必然采取某种行为。

### 1.2 架构边界

-   **WeChatAgent 插件：**
    捕获、规范化事件，转发输入，接收策略并执行发送、排队、静默或唤醒候选等动作。
-   **Bio-Mood Engine：**
    唯一权威的持久化状态、时间推进、周期、睡眠、压力、调节、情绪和行为倾向计算方。
-   **DSH：**
    使用角色卡、关系、上下文、群规则和引擎状态摘要，判断是否回复并生成自然语言。
-   **插件：** 只负责执行交付，不负责重新计算引擎状态。

本轮只扩展 **05 生理周期模块** 的派生参数，以及 **09 情绪计算引擎**
对这些参数的消费。引擎不生成自然语言；DSH
不计算或持久化引擎状态；插件不承担情绪计算。

角色卡硬规则与安全规则优先于引擎倾向。周期状态不得覆盖角色卡明确设定。

### 1.3 本轮不做

以下内容明确排除在本轮实现范围之外：

-   不新增独立月经模块。
-   不修改 08 调节模块的公式和输入。
-   不修改 10 人格行为映射模块的公式。
-   不新增 `intimacy_initiative` 等行为输出。
-   不引入随机症状波动。
-   不引入运行时 `cycle_day` 输入。
-   不引入独立 `luteal_length`。
-   不调整周期长度模型和阶段边界。
-   不新增阶段枚举或重命名现有阶段。
-   不把周期参数直接写入 07 压力状态。
-   不改变 DSH 的自然语言生成职责。

## 3. 新配置：角色级周期敏感度参数

新增配置路径：

``` json
{
  "cycle": {
    "profile": {
      "pain_sensitivity": 1.0,
      "luteal_sensitivity": 1.0,
      "mood_variability": 1.0,
      "intimacy_variability": 1.0
    }
  }
}
```

四个参数均为数值，允许范围 `[0, 1.5]`，默认值均为 `1.0`。

  ----------------------------------------------------------------------------------------------------------------------------------
  配置项                   作用范围                                                         不得影响
  ------------------------ ---------------------------------------------------------------- ----------------------------------------
  `pain_sensitivity`       仅调节 `pain_load`                                               焦虑、易激惹、积极情绪、亲密需求

  `luteal_sensitivity`     仅调节黄体期权重对应的焦虑与易激惹分量                           疼痛、积极情绪、亲密需求及非黄体期分量

  `mood_variability`       调节                                                             疼痛和亲密需求
                           `anxiety_delta`、`irritability_delta`、`positive_affect_delta`   

  `intimacy_variability`   仅调节 `intimacy_need_delta`                                     疼痛、焦虑、易激惹、积极情绪
  ----------------------------------------------------------------------------------------------------------------------------------

兼容要求：

-   新配置默认版本为 `config_version = 2`。
-   旧配置没有 `cycle.profile` 时，迁移后补齐四个默认值。
-   旧配置若已有 `cycle.profile`
    或其中部分显式值，必须保留已有显式值，只补齐缺失项。
-   不得因迁移而覆盖用户已经设置的配置。
-   配置值类型错误、非有限数值或超出范围时，应按统一配置校验规则报错，不得静默修正。

## 4. 05 生理周期模块：九维 phase_impact

### 4.1 新向量结构

新版本 `phase_impact` 必须包含且只包含以下九个字段：

``` js
{
  physical_comfort: 0,       // 非疼痛性的身体舒适度，范围 [-1, 1]
  energy: 0,                 // 精力倾向，范围 [-1, 1]
  sensitivity: 0,            // 敏感度倾向，范围 [-1, 1]
  social_drive: 0,           // 社交驱动力倾向，范围 [-1, 1]
  pain_load: 0,              // 疼痛负荷，范围 [0, 1]
  anxiety_delta: 0,          // 焦虑倾向增量，范围 [-1, 1]
  irritability_delta: 0,     // 易激惹倾向增量，范围 [-1, 1]
  positive_affect_delta: 0, // 积极情绪倾向增量，范围 [-1, 1]
  intimacy_need_delta: 0    // 亲密需求倾向增量，范围 [-1, 1]
}
```

### 4.2 `physical_comfort` 语义调整

在九维新结构中，`physical_comfort`
明确表示**不包含疼痛负荷的身体舒适度**。疼痛由独立的 `pain_load`
表达，避免疼痛被重复计算。

因此，原阶段矩阵中的 `physical_comfort` 值需要调整：

  阶段                新 physical_comfort
  ----------------- ---------------------
  menstrual_like                    -0.04
  follicular_like                   +0.05
  ovulatory_like                    +0.03
  luteal_like                       -0.05

`energy`、`sensitivity`、`social_drive` 的阶段矩阵值完全沿用旧值。

### 4.3 新维度阶段矩阵

以下为首轮设计初值，属于待仿真校准参数，不应被描述为医学事实：

  -----------------------------------------------------------------------------------------------------------------
  阶段                 pain_load   anxiety_delta   irritability_delta   positive_affect_delta   intimacy_need_delta
  ----------------- ------------ --------------- -------------------- ----------------------- ---------------------
  menstrual_like            0.60           +0.15                +0.20                   -0.15                 -0.10

  follicular_like           0.05           -0.10                -0.10                   +0.20                 +0.05

  ovulatory_like            0.05           -0.05                -0.05                   +0.25                 +0.35

  luteal_like               0.20           +0.30                +0.35                   -0.10                 -0.05
  -----------------------------------------------------------------------------------------------------------------

### 4.4 阶段权重

必须使用现有阶段 crossfade 所对应的每阶段权重 `w_p(progress)`，并满足：

``` text
∀p: w_p(progress) >= 0
Σ_p w_p(progress) = 1
```

不能只保留混合后的总向量再尝试调节黄体期分量。因为 `luteal_sensitivity`
必须只作用于黄体期的焦虑、易激惹分量，所以计算时必须保留各阶段的独立权重和独立贡献。

阶段权重应由现有阶段进度与 crossfade
机制确定，不得引入新的随机数或离散跳变。

### 4.5 完整计算公式

令 `M[p][dimension]` 表示阶段 `p` 在相应维度的矩阵值，`w_p`
表示该阶段权重。`clamp(x, min, max)` 表示限幅函数。

``` text
pain_load =
  clamp(
    pain_sensitivity * Σ_p w_p * M[p][pain],
    0,
    1
  )

anxiety_delta =
  clamp(
    mood_variability *
    [
      Σ_{p != luteal_like} w_p * M[p][anxiety]
      + w_luteal_like * M[luteal_like][anxiety] * luteal_sensitivity
    ],
    -1,
    1
  )

irritability_delta =
  clamp(
    mood_variability *
    [
      Σ_{p != luteal_like} w_p * M[p][irritability]
      + w_luteal_like * M[luteal_like][irritability] * luteal_sensitivity
    ],
    -1,
    1
  )

positive_affect_delta =
  clamp(
    mood_variability * Σ_p w_p * M[p][positive_affect],
    -1,
    1
  )

intimacy_need_delta =
  clamp(
    intimacy_variability * Σ_p w_p * M[p][intimacy_need],
    -1,
    1
  )
```

约束：

1.  `luteal_sensitivity` 只乘以黄体期的焦虑和易激惹矩阵分量。
2.  `luteal_sensitivity`
    不得乘以混合后的整体结果，否则会错误放大非黄体期贡献。
3.  `mood_variability` 只作用于焦虑、易激惹和积极情绪。
4.  `pain_sensitivity` 只作用于疼痛负荷。
5.  `intimacy_variability` 只作用于亲密需求。
6.  上述五个新维度在 05 中完成限幅；09 不再重复限幅。
7.  阶段向量必须确定性计算。相同状态、时间、配置和输入应得到相同结果。
8.  本轮不增加随机症状波动。

### 4.6 首轮数值检查

默认 `pain_sensitivity = 1.0`，经期阶段权重为 1 时：

``` text
pain_load = 0.60
cycle_contrib.physical_comfort
  = 0.6 * (-0.04) - 0.20 * 0.60
  = -0.144
```

最大疼痛敏感度 `pain_sensitivity = 1.5` 时：

``` text
pain_load = 0.90
cycle_contrib.physical_comfort
  = 0.6 * (-0.04) - 0.20 * 0.90
  = -0.204
```

最小疼痛敏感度 `pain_sensitivity = 0` 时：

``` text
pain_load = 0
cycle_contrib.physical_comfort
  = 0.6 * (-0.04)
  = -0.024
```

以上均为 `cycleContribution()`
的**原始贡献值**，不是经过情绪惯性、时间步长和单步限幅后的最终状态变化。

## 5. 09 情绪计算引擎：消费新周期参数

### 5.1 保留原有通道

以下四个旧通道的系数必须保持为 `0.6`：

``` text
cycle.energy
  = 0.6 * phase_impact.energy

cycle.sensitivity
  = 0.6 * phase_impact.sensitivity

cycle.social_drive
  = 0.6 * phase_impact.social_drive

cycle.physical_comfort
  = 0.6 * phase_impact.physical_comfort
```

原有 `cycle_sensitivity` → `stability` 路径必须保留：

``` text
-0.3 * (cycle_sensitivity - 0.5)
```

`cycle_sensitivity` 是 08 已有调节标量；`anxiety_delta` 是 05
新增周期派生量。两者是独立输入，不得合并、互相替代或遗漏。

### 5.2 新权重与初始值

下列系数为首轮仿真初值，后续可依据测试和仿真结果校准。实现时应集中定义，避免散落魔法数字。

  -------------------------------------------------------------------------------------
  系数              映射                                  允许范围               初始值
  ----------------- ------------------------- -------------------- --------------------
  `w_pain_pc`       `pain_load` →                      `[0, 0.30]`               `0.20`
                    `physical_comfort` 负向                        

  `w_pain_energy`   `pain_load` → `energy`             `[0, 0.20]`               `0.10`
                    负向                                           

  `w_anx_stab`      `anxiety_delta` →                  `[0, 0.25]`               `0.15`
                    `stability` 负向                               

  `w_anx_sens`      `anxiety_delta` →                  `[0, 0.20]`               `0.10`
                    `sensitivity` 正向                             

  `w_irr_stab`      `irritability_delta` →             `[0, 0.20]`               `0.12`
                    `stability` 负向                               

  `w_irr_sens`      `irritability_delta` →             `[0, 0.20]`               `0.12`
                    `sensitivity` 正向                             

  `w_pos_stab`      `positive_affect_delta` →          `[0, 0.20]`               `0.10`
                    `stability` 正向                               

  `w_pos_social`    `positive_affect_delta` →          `[0, 0.20]`               `0.10`
                    `social_drive` 正向                            

  `w_intimacy`      `intimacy_need_delta` →            `[0, 0.35]`               `0.25`
                    `closeness_need` 正向

### 5.3 完整 cycle contribution 公式

``` text
cycle_contrib.physical_comfort =
    + 0.6 * phase_impact.physical_comfort
    - w_pain_pc * phase_impact.pain_load

cycle_contrib.energy =
    + 0.6 * phase_impact.energy
    - w_pain_energy * phase_impact.pain_load

cycle_contrib.stability =
    - 0.3 * (cycle_sensitivity - 0.5)
    - w_anx_stab * phase_impact.anxiety_delta
    - w_irr_stab * phase_impact.irritability_delta
    + w_pos_stab * phase_impact.positive_affect_delta

cycle_contrib.sensitivity =
    + 0.6 * phase_impact.sensitivity
    + w_anx_sens * phase_impact.anxiety_delta
    + w_irr_sens * phase_impact.irritability_delta

cycle_contrib.social_drive =
    + 0.6 * phase_impact.social_drive
    + w_pos_social * phase_impact.positive_affect_delta

cycle_contrib.closeness_need =
    + w_intimacy * phase_impact.intimacy_need_delta

cycle_contrib.stress = 0
```

所有周期直接贡献仍归属
`contributions['mood.<dimension>'].cycle`。不得新增 contribution
source。

`stress` 仍由 07 模块权威管理；05/09 不得直接写入压力状态。

### 5.4 惯性、时间步长和限幅

09 现有情绪维度的
home、tau、惯性和单步限幅规则继续生效。新增周期贡献必须进入既有计算流水线，不能绕过惯性直接写状态。

当前相关规则：

-   `physical_comfort` 的 tau 为 4 小时。
-   常规单步变化上限为 0.06。
-   严重事件单步上限为 0.12。
-   绝对断言阈值为 0.15。
-   `dt = 0` 时惯性系数 `alpha = 0`，只有既有噪声路径可能生效。
-   噪声不得被用于制造周期向量的随机变化。

经期默认参数在 `dt = 3600s`、`tau = 4h` 时：

``` text
alpha = 1 - exp(-3600 / (4 * 3600))
      ≈ 0.221199
```

注意：如项目当前实际实现采用其他精确定义，应以冻结契约和代码公式为准；测试必须明确区分原始
contribution 与经过惯性、限幅后的实际状态增量。不得把原始值 `-0.144`
误写成单步状态变化值。

检查 `lib/core/constants.mjs`、`lib/core/coordinator.mjs` 及所有模块
`index.mjs`，确认没有硬编码的 `interface_version: 1` 或等价常量。

### 6.3 cycle.model_version 升级时机

`cycle.model_version` 升级必须发生在 `updateCycle()`
的最终状态组装/返回路径中，确保无论本次是否推进周期日、`dt` 是否为
0、是否跨越阶段，第一次执行新算法后状态版本都更新为 2。

**不得只在 `advanceCycleDays()` 中升级版本。**
否则当周期不推进时，旧状态可能一直保留 model_version 1。

### 6.4 mood.model_version 持久化

09 不仅要在 diagnostics 中报告 `model_version = 2`，还必须将 mood
状态中的 `model_version` 实际更新为
2。测试必须验证返回状态，而不是只检查 diagnostics。

### 6.5 配置迁移入口

桌面 Agent 必须先检查 `lib/core/models.mjs`、状态加载/初始化路径和
coordinator 的实际调用顺序，再确定唯一迁移入口，并在契约中写清楚。

目标行为：

-   新建状态直接使用 `config_version = 2`，并具备完整默认 profile。
-   旧配置在加载/规范化阶段迁移到 v2。
-   缺少 `cycle.profile` 时补齐四个默认值。
-   已存在的显式 profile 值必须保留，只补缺失值。
-   迁移完成后配置版本更新为 2。
-   不允许配置已标记为 v2，却缺少必需字段或只完成一半迁移。
-   不允许每个模块各自执行一套不同的配置迁移。
-   不允许把配置迁移混入周期时间推进逻辑。

### 6.6 旧四维与新九维 phase_impact 兼容

09 必须识别两种且仅两种合法形状：

**旧版 v1：恰好四个字段**

``` js
{
  physical_comfort,
  energy,
  sensitivity,
  social_drive
}
```

旧版 `physical_comfort` 是复合语义，可能已经包含疼痛影响。兼容时：

-   接受旧四维输入。
-   将缺失的五个新维度按 0 处理。
-   不再额外从 `pain_load` 扣减，避免重复计算疼痛。
-   旧四维的 `physical_comfort` 按旧语义消费。

**新版 v2：恰好九个字段**

``` js
{
  physical_comfort,
  energy,
  sensitivity,
  social_drive,
  pain_load,
  anxiety_delta,
  irritability_delta,
  positive_affect_delta,
  intimacy_need_delta
}
```

新版 `physical_comfort` 是非疼痛舒适度；疼痛通过 `pain_load`
单独进入贡献公式。

**必须拒绝的输入：**

-   缺少任意一个旧四维必需字段。
-   只包含五至八个字段的部分新结构。
-   新旧字段混合但不构成完整合法形状。
-   `null`、字符串、布尔值等非数值字段。
-   `NaN`、`Infinity`、`-Infinity`。
-   未知额外字段。
-   超出各字段定义范围的数值。

不得将任意缺失字段都静默补
0；只有识别为**恰好四字段的旧版结构**时，才允许把五个新维度视为 0。

### 6.7 09 严格错误行为

09 对越界输入不得静默裁剪。必须抛出 `MODULE_FAILED`，错误 details
至少包含：

``` js
{
  code: 'MODULE_FAILED',
  details: {
    module: 'mood',
    path: 'inputs.cycle.phase_vector.pain_load',
    got: 1.2
  }
}
```

实际项目可能通过既有错误包装器表达 `code` 和
`details`；应遵循统一错误契约，但必须保留 `module`、精确 `path` 和原始
`got` 值。

失败时不得返回伪装成成功的正常 `ModuleResult`。由 coordinator
的既有错误路径记录失败。

每小时变化 = 0.825 / 24

-   menstrual_like → follicular_like
-   ovulatory_like → luteal_like
-   luteal_like → menstrual_like（周期回绕）

## 12. 最终设计原则

本轮实现必须遵循以下原则：

1.  05 负责周期阶段和周期派生参数；09 负责将这些参数映射为 mood
    contribution。
2.  `physical_comfort` 与 `pain_load` 分离，避免疼痛重复计入。
3.  黄体期敏感度必须按黄体期阶段权重单独调制，保证 crossfade 连续。
4.  四个 profile 参数严格隔离，各自只影响授权维度。
5.  周期向量确定性计算，不引入随机波动。
6.  旧四维输入按旧语义兼容；新九维输入按新语义处理；不接受不完整或含糊结构。
7.  版本迁移必须真实写入状态，不能只改变 diagnostics。
8.  08、10 和插件/DSH 职责边界保持不变。
9.  先冻结契约，再实现代码；先完成单模块测试，再集成。
10. 所有参数初值都应视为可仿真校准的工程参数，不应包装成生理学定律。

## 2. 术语与枚举

### 2.1 标识符

| 名称 | 规则 | 示例 |
| --- | --- | --- |
| `character_id` | `^[a-z][a-z0-9_-]{0,63}$` | `whale_character` |
| `event_id` | `^[A-Za-z0-9_-]{8,128}$` | `evt_20261109_ab12cd34` |
| `idempotency_key` | 与 `event_id` 相同，或调用方提供的稳定键（字符集 `^[A-Za-z0-9_-]{8,128}$`） | `evt_20261109_ab12cd34` |
| `source_key` | `wechat:<conversation_id>:<sender_id>`，或系统生成事件用 `silence:<conversation_id>`；系统生成的管理事件允许 `wechat:admin:admin` 作为兜底标识（13 未注入 `admin_source_key` 时） | `wechat:group_123:sender_a1` |
| `conversation_id` | 1–128 字符，不透明字符串 | `group_123` |
| `sender_id` | 1–128 字符，不透明字符串；**不得**存原始 wxid 明文到日志 | `sender_a1` |
| `request_id` | UUID v4 或 32 位十六进制 | `9f2c...` |
| `reason_code` | `^[a-z][a-z0-9_]{0,63}$` | `sleeping_low_urgency` |

`event_id` 只校验字符集与长度；`evt_` 前缀是推荐风格，**不强制**。`idempotency_key` 不得包含 `:`，系统生成事件也必须满足该字符集。

**幂等键的选取优先级（v1.7.11，P1-C；仅 12 的 HTTP 层适用）**：`Idempotency-Key` 请求头 > `body.idempotency_key` > `body.event_id`。三者皆缺 → `400 INVALID_REQUEST`；请求头与 body 都提供且不相等 → `400 INVALID_REQUEST`（`details.reason='idempotency_key_conflict'`），不得静默取其一。§12.3 的示例里 `idempotency_key` 与 `event_id` 相同只是惯例，不构成"必须相等"的约束；插件模式（13）不经 HTTP，直接传 `event_id` 作为键。

### 2.2 时间格式

- 统一使用 **UTC ISO 8601，毫秒精度，必须带 `Z`**：`2026-11-09T09:20:01.000Z`。
- 不接受无时区、秒级无毫秒、Unix 秒、本地时间字符串。
- 角色本地时区单独保存为 IANA 名称：`Asia/Shanghai`。
- 本地时间计算必须使用 `Intl.DateTimeFormat`（Node 内置），不得手写 UTC 偏移，避免夏令时错误。

### 2.3 事件类型 `event_type`

| 值 | 含义 | 基础强度 | 衰减档 |
| --- | --- | --- | --- |
| `group_message` | 普通群消息 | 0.02 | `fast` |
| `mention` | 被 @ | 0.08 | `medium` |
| `important_person_appear` | 重要人物出现/发言 | 0.12 | `slow` |
| `comfort_received` | 收到安慰/关心 | −0.10 | `medium` |
| `conflict` | 冲突、批评、争执 | 0.25 | `slow` |
| `long_silence` | 长时间无互动 | 0.05 | `very_slow` |
| `direct_question` | 需要回应的直接提问 | 0.06 | `medium` |
| `admin_command` | 管理员指令 | 0.00 | `none` |
| `system_event` | 系统事件 | 0.00 | `none` |

负强度表示降低压力。所有强度最终都进入 `stress.level`，**不得**直接写入 `mood`。

### 2.4 关系标签 `relationship_tag`

`sender` 的 `relationship_tag` 只允许：

`ordinary` · `important` · `intimate` · `conflict` · `admin` · `unknown`

未知时必须用 `unknown`，不得根据消息内容猜测。

### 2.5 周期阶段 `cycle.phase`

`menstrual_like` · `follicular_like` · `ovulatory_like` · `luteal_like`

名称必须保留 `_like` 后缀，表明是角色模拟阶段。

### 2.6 睡眠状态 `sleep.state`

合法转换见 `06-睡眠模块.md`；非法转换必须抛 `MODULE_FAILED` 或返回警告，不得静默跳转。

### 2.7 交付策略 `delivery.policy`

`deliver_now` · `queue_until_awake` · `silent_ignore` · `wake_candidate` · `urgent_interrupt`

## 4. 模块函数契约

### 4.1 统一签名

每个模块必须导出一个纯函数，参数使用对象形式：

```js
/**
 * @param {object} params
 * @param {object} params.previous   上一时刻的模块状态（只读）
 * @param {object} params.inputs     本模块需要的输入（只读）
 * @param {string} params.now        UTC ISO 毫秒时间
 * @param {object} params.rng        RandomStream 实例
 * @param {object} params.config     本模块配置（只读）
 * @returns {ModuleResult}
 */
export function updateModule({ previous, inputs, now, rng, config }) {}
```

**时间差量 `inputs.dt`**：任何使用 `Δ` 计算惯性/衰减的模块（当前为 08、09）必须在 §4.2 的 `inputs` 表中声明 `dt`（integer，单位秒，`≥ 0`）。02 按实际步长传入：chunk 循环内为当前 chunk 的秒数，细分重算为到提示时刻的秒数，"应用事件"阶段为 `floor((effective_now - t) / 1000)`（通常为 0，时钟回退/`elapsed=0` 时也取 0）。模块**不得**从 `now - last_tick_at` 自行推算，也**不得**兜底默认值；`inputs.dt` 缺失或不是非负整数即 `MODULE_FAILED`。

### 4.2 返回值

```js
/**
 * @typedef {Object} ModuleResult
 * @property {object} state                                      下一时刻模块状态
 * @property {Record<string, Record<string, number>>} contributions
 *           贡献分解：维度 -> 来源 -> 有符号变化量；无变化也必须出现 0
 * @property {string[]} reason_codes                             稳定原因码，最多 16 个
 * @property {string[]} warnings                                 非致命问题，最多 16 个
 * @property {string|null} next_transition_at                    下一个内部状态转换时刻（UTC ISO）；无则 null
 * @property {object} [derived]                                  可选：不持久化、仅供下游模块消费的派生量（见下）
 * @property {{module:string, model_version:number, interface_version:number, elapsed_ms:number}} diagnostics
 */
```

`derived` 是**模块间传参通道**，语义固定：

- 不写入 `state`、不持久化、不进 `evlog`、不返回给 API/适配层；
- 只在同一次 `runPipeline` 内由协调器按模块顺序传递，生命周期止于本次 `advance`；
- 键名必须与下游模块文档声明的读取路径一致，未知键由协调器忽略并追加 `UNKNOWN_DERIVED_KEY`；
- 目前定义的键（白名单，白名单外的键由协调器丢弃并追加 `UNKNOWN_DERIVED_KEY`）：
  - `derived.phase_impact`（05 输出，`{physical_comfort, energy, sensitivity, social_drive}` 四维原始阶段向量，含交叉淡入结果），由协调器作为 `inputs.cycle.phase_vector` 传给 09。
  - `derived.event_intensity`（07 输出，`number`）：本次新事件经 `computeIntensity` 计算的最终强度，用于 02 判定 `severe` 与 09 的 `inputs.event.intensity`。三件事固定：① 类型是 `number`，不是 `number|null`；② 唯一输出点是 `applyEvent`（`updateStress` 绝不输出 `derived`）；③ 纯时间推进（`event === null`）或 07 未运行时**省略该键**。
- **降级时不输出**：模块无法产生该派生量时**省略整个 `derived` 键**（不得输出全 0 占位），由下游按自身降级规则处理（如 09 缺 `phase_impact` 时按全 0 向量计算并追加 `MISSING_CYCLE_DATA`）。同一警告码在 `diagnostics.warnings` 中按去重处理（02 §5.5）。

`next_transition_at` 的语义：

- 只用于让协调器把 1 小时的时间片切得更细，不参与数值计算；
- 必须是 UTC ISO 毫秒时间，且满足 `now < next_transition_at ≤ now + 1h`；否则忽略并追加 `INVALID_TRANSITION_HINT`；
- 同一时间片内所有模块的提示取**最早值**；协调器每个小时片最多再切分 8 次，防止提示抖动导致过细步进；
- 模块不得用它表达"未来某个事件一定会发生"，只能表达"若时间推进到该点，状态机必须重新判定"。

`diagnostics.interface_version` 固定为 `1`，用于 14 的接口兼容测试；改变模块输入输出形状必须提升该值并走契约变更流程。

### 4.3 硬性要求

1. 不修改 `previous` / `inputs` / `config`；必须返回新对象。
2. 不调用 `Date.now()`、`new Date()`、`performance.now()`；只使用传入的 `now`。
3. 不访问网络、文件系统、数据库、环境变量。
4. 随机性只能通过 `rng` 获取；不得调用 `Math.random()`。
5. 所有数值输出必须有限、在契约范围内；不得出现 `NaN`、`Infinity`、`-0`。
6. 失败必须抛出带 `code` 的 `Error`，或返回带 `warnings` 的降级结果；不得静默吞错。
7. 返回值必须可 `JSON.stringify`；不得包含函数、`BigInt`、`undefined`、循环引用。

### 4.4 持久化精度

- 内存计算使用双精度浮点。
- 写入持久化或 API 响应前，所有数值统一 `round6`：`Math.round(v * 1e6) / 1e6`。
- 贡献值允许为负，范围 `[-1, 1]`，同样 `round6`。
- 禁止输出 `-0`；`round6` 后如为 `-0`，改为 `0`。

## 5. 时间契约

### 5.1 时间字段

| 字段 | 含义 | 允许关系 |
| --- | --- | --- |
| `occurred_at` | 事件实际发生时间（微信侧） | 可早于 `received_at` |
| `received_at` | 插件收到事件时间 | ≥ `occurred_at - 5 分钟` |
| `now` | 本次状态推进使用的有效时间 | ≥ `last_tick_at - 5 分钟` |

### 5.2 时钟回拨与未来时间

- 若 `now < last_tick_at - 5 分钟`：不倒退状态，令 `effective_now = last_tick_at`，追加 `CLOCK_REGRESSION`。
- 若 `now` 在 `[last_tick_at - 5 分钟, last_tick_at]`：令 `effective_now = last_tick_at`，追加 `CLOCK_TOLERATED`。
- 若 `occurred_at > received_at + 5 分钟`：令 `occurred_at = received_at`，追加 `FUTURE_OCCURRED_AT`。
- 若 `occurred_at` 早于 `last_tick_at - 180 天`：仍记录事件，但不回放历史状态；追加 `EVENT_TOO_OLD`，只按当前状态施加衰减后的剩余影响。

### 5.3 离线推进

- `elapsed = effective_now - last_tick_at`。
- 单步最大 `1 小时`；按 `chunk = min(elapsed, 1h)` 循环。
- 最多 `4320` 步（180 天）。超过时：
  1. 先按 4320 步推进到 `now - 180 天`；
  2. 剩余时间执行 `coarse_forward`：情绪向 home 收敛、睡眠债按日均值变化、周期按天数取模推进；
  3. 追加 `LONG_OFFLINE_COARSE:<小时>h`（如 `LONG_OFFLINE_COARSE:720h`），在 `warnings` 中记录实际跨度；警告码本体为 `LONG_OFFLINE_COARSE`，跨度是后缀参数（参数化规则同 `MISSING_<MODULE>_DATA`）。
- 禁止用 `while (elapsed > 0)` 无上限循环。

### 5.4 更新流水线（固定顺序）

```text
1. 校验输入与时间
2. 加载状态快照
3. 计算 elapsed 并按 1 小时分块
4. 推进周期与昼夜节律
5. 推进睡眠状态与睡眠债
6. 衰减旧压力/事件影响
7. 应用新事件（仅写入 stress）
8. 计算神经调节特征
9. 更新情绪状态
10. 生成行为上下文与消息策略
11. 原子保存新状态、事件日志与幂等记录
```

任何模块失败时：整个事务回滚，`state_version` 不变，返回错误；不得保存半成品状态。

### 5.4.1 事件即时生效

第 7 步应用新事件后，必须在**同一次推进内**重新计算 `stress.level`，不得等到下一次事件才生效：

```text
target_after = clamp(0.15 + Σ remaining_after, 0, 1)
level += (target_after - level) * 0.5        // 即时响应系数 0.5
level = clamp(level, 0, 1)
单次变化 ≤ 0.30（超出裁剪并追加 CLAMPED_DELTA）
```

后续每个时间片仍按半衰期 30 分钟的规则趋近目标。这样"收到冲突消息"会在本次调用返回时立刻体现压力上升，而不是延迟到下一次消息。

### 5.4.2 时间片细分

若任一模块返回合法的 `next_transition_at`，协调器必须把当前 1 小时片在该时刻切开，先推进到该时刻并重新调用全部模块，再继续剩余时间。规则见 §4.2；每小时最多细分 8 次。

## 6. 随机契约

### 6.1 算法

- PRNG：**PCG32**（XSH RR 输出），64 位状态，奇数增量。
- 64 位运算必须使用 `BigInt`，不得用 JS 32 位位运算模拟 64 位。
- 算法标识：`algorithm: "pcg32"`，`algorithm_version: 1`。

### 6.2 子种子派生

```text
message = master_seed_hex + "|" + character_id + "|" + stream_label + "|" + algorithm_version
digest  = BLAKE2b-512( UTF-8(message) )        // Node: crypto.createHash('blake2b512')
seed_hex = digest 的前 32 个十六进制字符       // 128 位
state_seed = seed_hex 前 16 个十六进制字符     // 转 BigInt，作为 PCG32 initstate
sequence   = seed_hex 后 16 个十六进制字符     // 转 BigInt，作为 PCG32 initseq
```

- `stream_label` 必须包含唯一上下文，例如 `cycle`、`sleep`、`mood`、`event`、`delivery`、`cycle:3`、`event:evt_...`。
- 同一 `stream_label` 必须得到同一子种子；不得消费父流来派生。
- 保存 `seed_hex` 与 `counter`；恢复时从 `seed_hex` 重建流并快进 `counter` 次，或直接保存 PCG 内部状态（二选一，但必须测试一致）。

### 6.3 金向量（实现必须逐项匹配）

**参考向量（PCG32 官方示例）：**

```text
initstate = 42
initseq   = 54
前 6 个 nextU32():
0xa15c02b7, 0x7b47f409, 0xba1d3330, 0x83d2f293, 0xbfa4784b, 0xcbed606e
```

**项目派生向量：**

```text
master_seed_hex = 000102030405060708090a0b0c0d0e0f
character_id    = whale_character
stream_label    = cycle
algorithm_version = 1

seed_hex  = 764d289e285a86b68df58ef666b4c9ab
state_seed = 0x764d289e285a86b6
sequence   = 0x8df58ef666b4c9ab

前 5 个 nextU32():
0x3e60b694, 0x5b31491f, 0x28f715f3, 0x15b85784, 0x3803ea34

前 5 个 nextFloat()（9 位小数）:
0.243663226, 0.356220789, 0.160020229, 0.084844084, 0.218809736
```

### 6.4 随机流隔离

- 每个模块只使用自己的流；`mood` 多取一个随机数不得改变 `cycle` 的结果。
- 事件级随机使用 `event:${event_id}` 派生；周期级随机使用 `cycle:${cycle_index}` 派生。
- 并发调用时，同一流必须串行消费；不得共享可变 PCG 实例。

## 7. 数值与防重复计入

### 7.1 数值约定

- 所有持久化状态维度：`[0, 1]`。
- 贡献值：`[-1, 1]`。
- 时间：秒（`elapsed_seconds`）为整数；毫秒只用于耗时诊断。
- 阈值比较统一使用 `1e-9` 容差。
- 展示层 `0–100` 只在 UI/API 的可选 `display` 字段出现，不进入计算。

### 7.2 单一通道原则（强制）

| 影响因素 | 唯一写入目标 | 禁止再次写入 |
| --- | --- | --- |
| 睡眠 | `sleep.*`；通过 `mood` 的 `sleep` 贡献影响情绪 | 不得直接写 `stress.level` |
| 周期 | `cycle.*`；通过 `mood` 的 `cycle` 贡献影响情绪 | 不得直接写 `stress.level`、`sleep.*` |
| 外部事件 | `stress.level` 与 `stress.active_events` | 不得直接写任何 `mood.*` |
| 压力 | `stress.level`；通过 `mood` 的 `stress` 贡献影响情绪 | 不得再次以 `event` 名义写入情绪 |
| 神经调节 | `regulation.*`；通过 `mood` 的 `regulation` 贡献影响情绪 | 不得直接写 `cycle.*`、`sleep.*` |
| 情绪恢复 | `mood` 的 `recovery` 贡献 | 不得写入其他模块 |
| 随机扰动 | `mood` 的 `noise` 贡献，幅度 ≤ 0.008 | 不得放大到覆盖真实输入 |

**在 v1 中，`contributions['mood.<dim>'].event` 必须恒为 `0`。** 事件的所有影响先进入 `stress.level`，再由 `stress` 单一通道影响情绪。违反此条视为契约错误。

> **注（v1.7.13，P-08-01）**：08 的六个目标公式读取 `cycle_*` / `sleep_*` / `stress`，属于**上下文特征**，不是第二条影响通道。它们只塑造 08 的稳态目标，输出还要经过 45 分钟惯性 `blend = 1 - 2^(-dt/2700)` 与单步 `0.05` 裁剪，不是原始值的转发；09 对 `regulation` 的贡献系数固定为 `0.10`（`closeness_need` 为 `0.08`）并再乘 `alpha[d]`。因此「直接通道 + 上下文特征」的合计冲击受两条独立上限约束（本文件 §7.3 的 `0.06`/`0.12` 与 08 §5.4 的 `0.05`），不构成重复写入或重复影响，无需删除 08 的输入项。

### 7.3 数值上限

- 单次更新任一情绪维度变化绝对值：普通更新 ≤ `0.06`；高严重度事件（`intensity ≥ 0.7`）≤ `0.12`——超出即裁剪到上限并追加 `CLAMPED_DELTA`；硬上限 `0.15` 为**断言**：单步 `|delta| > 0.15` 不裁剪，抛 `MODULE_FAILED` 并回滚（与 09 §5.3、02 §5.6 同一道防线）。
- **v1 可达性说明（v1.7.7）**：`0.12` 档为防御性上限。事件阶段 `inputs.dt` 恒为 0（chunk 循环结束时 `t` 已等于 `effective_now`），09 的惯性来源乘 `alpha` 后均为 0，事件当轮 `delta_raw` 只剩噪声，因此实际单步上限是后续 chunk 的 `0.06`；事件冲量经 `stress.level` 在后续 chunk 释放（00 §5.4.1）。`derived.event_intensity` 仍保留，用于 09 判 `severity_high` 与未来扩展。
- 单次更新任一调节特征变化绝对值 ≤ `0.05`。
- 单次更新 `sleep.sleepiness` 变化绝对值 ≤ `0.20`。
- 单次更新 `stress.level` 变化绝对值 ≤ `0.30`。

## 9. 错误与降级

### 9.1 错误对象

```js
const err = new Error('human readable message');
err.code = 'INVALID_REQUEST';
err.retryable = false;
err.details = {};
```

### 9.2 错误码表

| code | HTTP | retryable | 含义 |
| --- | --- | --- | --- |
| `INVALID_REQUEST` | 400 | false | 字段缺失、类型错误、越界 |
| `INVALID_TIME` | 400 | false | 时间格式错误或不可解析 |
| `UNAUTHORIZED` | 401 | false | 缺少/错误令牌 |
| `FORBIDDEN_CHARACTER` | 403 | false | 令牌无权访问该角色 |
| `NOT_FOUND` | 404 | false | 角色或状态不存在 |
| `DUPLICATE_EVENT` | 200 | false | 幂等键已处理；返回首次结果（12 §5.4），禁止用 409 |
| `STATE_VERSION_CONFLICT` | 409 | true | 乐观锁冲突，可重读后重试 |
| `RATE_LIMITED` | 429 | true | 限流 |
| `PAYLOAD_TOO_LARGE` | 413 | false | body 超过 64 KiB，读取阶段即拒绝 |
| `UNSUPPORTED_MEDIA_TYPE` | 415 | false | `Content-Type` 不是 `application/json` |
| `CLOCK_REGRESSION` | 200 | false | 时钟回拨，已钳制 |
| `MODULE_FAILED` | 500 | false | 模块内部错误，事务已回滚 |
| `STORAGE_FAILED` | 503 | true | 存储不可用或写失败 |
| `DEGRADED` | 200 | true | 使用缓存快照或降级结果 |
| `INTERNAL` | 500 | false | 未分类错误 |

**200 类码的信封（v1.7.9，W6-2）**：`DUPLICATE_EVENT` / `CLOCK_REGRESSION` / `DEGRADED` 一律走**成功信封** `{ok:true, data}`，**不得**走 `error` 分支：`DUPLICATE_EVENT` 由 `data.duplicate=true` 表达，`CLOCK_REGRESSION` 与 `DEGRADED` 由 `data.diagnostics.warnings` 表达。12 的 `/v1/events` 与 `/v1/tick` 永不返回 `error.code='DEGRADED'`（远程模式下 `DEGRADED` 本就不该出现——它是主聊天作用域的产物，只在 13 的插件模式出现）。

### 9.2.1 警告码（不是错误码）

以下值只出现在 `warnings` / `diagnostics.warnings`，不映射 HTTP 状态，不触发事务回滚：

| 警告码 | 含义 |
| --- | --- |
| `STORAGE_EVICTED` | 已按 §11.5 淘汰最旧数据以回到预算内 |
| `INVALID_TRANSITION_HINT` | 模块给出的 `next_transition_at` 非法，已忽略 |
| `NON_PRIMARY_READONLY` | 已绑定主聊天，但当前聊天不是主聊天，已只读降级（预期行为） |
| `PRIMARY_UNBOUND` | `primary_chat_id` 未配置，写操作 fail-closed，需管理员 `bind_primary`（配置缺失） |
| `CLOCK_REGRESSION` | 回拨超过 5 分钟，`effective_now` 被钳制 |
| `CLOCK_TOLERATED` | 回拨在 5 分钟内，已容忍 |
| `FUTURE_OCCURRED_AT` | `occurred_at` 超前，已钳制到 `received_at` |
| `EVENT_TOO_OLD` | 事件超过 180 天，只记录不回放历史 |
| `LONG_OFFLINE_COARSE` | 离线超过 4320 步，已启用粗推进；实际跨度以后缀参数记录（`LONG_OFFLINE_COARSE:<小时>h`） |
| `CLAMPED_DELTA` | 某字段变化超过上限，已裁剪 |
| `INPUT_CLAMPED` | 上游输入越界，已钳制到合法区间 |
| `DUPLICATE_EVENT_ID` | 同一 `event_id` 不同幂等键，日志只保留先到的一条 |
| `LOW_CONFIDENCE_CYCLE` | 周期数据置信度低，已按低置信度处理 |
| `MISSING_<MODULE>_DATA` | 可选模块数据缺失，已用契约默认值 |
| `UNKNOWN_CONFIG_KEY` | 配置中存在未知键，已忽略并告警 |
| `UNKNOWN_DERIVED_KEY` | 模块 `derived` 中出现下游未声明的键，已忽略 |
| `MIGRATION_DEFERRED` | 只读路径遇 `schema_version < target`，未迁移，返回原状态（迁移留给下一次写路径） |
| `STORAGE_OVER_BUDGET` | 只读路径检测到五键合计超预算，未淘汰，返回原状态 |
| `RECOVERY_DEFERRED` | 只读路径检测到未完成的 `tx_journal`，未恢复，返回已提交版本 |

**`warnings` 不受 `reason_code` 正则约束**（§2.1 的 `^[a-z][a-z0-9_]{0,63}$` 只适用于 `reason_codes`）。参数化警告统一使用 `<CODE>:<param>` 格式，其中 `<CODE>` 部分仍需匹配 `^[a-z][a-z0-9_]{0,63}$`（如 `LONG_OFFLINE_COARSE:720h`、`MISSING_SLEEP_DATA`）。14 的契约测试扫描 `warnings` 时必须使用放宽后的正则（允许冒号与参数后缀），不得直接复用 `reason_code` 正则，否则会误报。

**`details.warnings` 的口径**（`saveState` 等返回对象的附加承载位）：复用本表码表，不得自造码；单次返回不超过 3 条；不要求去重（一次 `saveState` 最多产生 0–2 条）；不映射 HTTP 状态、不触发回滚，处理方式与 `diagnostics.warnings` 一致。

### 9.3 降级原则

- API/网络不可用：使用最近一次状态快照，返回 `DEGRADED`；不得阻塞正常聊天。
- 某个可选模块数据缺失：使用契约默认值，追加 `MISSING_<MODULE>_DATA`；不得编造观测值。
- 持久化失败：本次推进视为失败，不更新内存中的权威状态；返回错误。
- 不得无限重试；最多 2 次短重试（指数退避 200ms/600ms），之后降级。

## 10. 日志与隐私

### 10.1 每次状态推进必须记录

```json
{
  "ts": "2026-11-09T09:20:01.000Z",
  "level": "info",
  "event_id": "evt_...",
  "character_id": "whale_character",
  "state_version_before": 42,
  "state_version_after": 43,
  "occurred_at": "2026-11-09T09:20:00.000Z",
  "processed_at": "2026-11-09T09:20:01.000Z",
  "elapsed_seconds": 60,
  "module_ms": {"cycle": 1, "sleep": 2, "stress": 1, "regulation": 1, "mood": 3, "behavior": 1},
  "reason_codes": ["sleeping", "low_event_urgency"],
  "contributions": {"mood.energy": {"sleep": -0.03}},
  "error_code": null
}
```

### 10.2 禁止记录

- 完整消息正文、完整私聊内容、图片/语音内容；
- 原始 wxid、手机号、地址、令牌、Cookie、API Key；
- `master_seed_hex` 全量；只允许记录 `master_seed_id`（`sha256(master_seed_hex)` 前 8 位十六进制）。

### 10.2.1 主种子的持久化与暴露边界

`master_seed_hex` 是**模拟状态的一部分**，必须随 `state` 一起持久化，否则重启后无法派生新的确定性随机流。具体规则：

| 位置 | 是否允许出现 | 说明 |
| --- | --- | --- |
| `state` 存储键 | 允许 | 唯一允许完整保存的位置 |
| 事件日志 / 幂等索引 / 元数据 / 快照 | 禁止 | 快照若包含状态，必须先脱敏 |
| 应用日志 / 错误详情 | 禁止 | 只允许 `master_seed_id` |
| API 响应 | 禁止 | `/v1/state` 必须把该字段替换为 `master_seed_id` |
| `before-context` 注入 | 禁止 | 只可使用摘要与行为上下文 |
| 打包产物 / 文档示例 | 禁止 | 示例种子只能用于测试（如 `000102...0e0f`） |

**唯一例外：`meta.state_backup`。** 迁移前写入的灾备快照允许包含完整 `state`（含 `master_seed_hex`），因为 `state` 键损坏时它是种子的唯一来源。约束：

1. 仅在迁移窗口内存在：迁移成功后立即删除；迁移失败可保留，并记 `migration_failed_at`。
2. 只允许一份，≤ 8 KiB。
3. 不得被 `evlog` / `idem` / `snapshots` / `cfg` 引用或复制。
4. 任何对外输出（API 响应、错误详情、日志、`export_diagnostics`、调试快照）必须先脱敏为 `master_seed_id`。
5. `meta.rollback_state` **不在例外内**：它随每次 `advance` 写入，必须脱敏（见 04 §5.3.1）。

`master_seed_hex` 不是安全凭据，泄露不会导致权限问题，但会破坏"角色状态不可预测"的体验，因此仍按敏感字段处理。

### 10.3 消息内容最小化

- 引擎只要求 `payload.text_hash`（SHA-256 十六进制）。
- `payload.text_summary` 可选，最多 120 字符；默认不发送。
- 适配层不得把群消息内容当作系统指令或配置；所有外部文本一律视为不可信数据。

### 10.4 日志保留

- 应用日志：最多 7 天或 20 MiB，滚动覆盖。
- 事件日志：默认 90 天；只保留 `event_id / type / time / source_key / intensity`，不保留正文。
- 状态历史：默认 30 天，每小时最多 1 个采样。

## 11. 持久化抽象

所有存储实现必须满足同一接口，模块不得直接依赖 `ctx.storage`、SQLite 或文件路径。

```js
/**
 * @typedef {Object} StateRepository
 * @property {(characterId:string) => Promise<object|null>} loadState
 * @property {(state:object, expectedVersion:number) => Promise<
 *   {ok:true, state_version:number} |
 *   {ok:false, code:string, details?:{warnings?:string[], reason?:string}}
 * >} saveState
 * @property {(characterId:string, idempotencyKey:string) => Promise<object|null>} findEventResult
 * @property {(record:object) => Promise<void>} appendEvent
 * @property {(characterId:string, limit:number) => Promise<object[]>} listRecentEvents
 * @property {(fn:(tx:Transaction)=>Promise<any>, opts?:{signal?:AbortSignal}) => Promise<any>} transaction
 * @property {(characterId:string, request:{operation:'reset_state'|'reset_seed'|'manual_cycle_correction', payload?:object, now:string, prepare?:(state:object, payload:object, now:string) => Promise<object>|object}) => Promise<
 *   {ok:true, operation:string, accepted_at:string, state_version:number} |
 *   {ok:false, code:string, details?:{recovery_required?:boolean, reason?:string}}
 * >} adminReset
 */
```

`saveState` 失败时 `details` 为可选字段：`details.warnings` 承载 `DEGRADED` 的原因（`NON_PRIMARY_READONLY` / `PRIMARY_UNBOUND`，口径见 §9.2.1），`details.reason` 承载存储层错误的补充说明。未提供时调用方只按 `code` 处理。

`details.reason` 取值集合固定为：`state_too_large` · `counter_too_large` · `migration_failed` · `recovery_required`。不得在错误分支自造其他字符串；14 的契约测试按此集合断言。

### 11.0 事务对象 `Transaction`

宿主只保证**单键**读写完整，不保证多键原子性。因此事务是"WAL + 补偿"方案，不是 ACID。所有实现在 `transaction(fn)` 内必须提供以下方法：

```js
/**
 * @typedef {Object} Transaction
 * @property {(key:string) => Promise<any>} get
 * @property {(characterId:string) => Promise<{state:object, version:number}|null>} getState
 * @property {(key:string, value:any) => Promise<void>} put
 * @property {(key:string) => Promise<void>} del
 * @property {(state:object, expectedVersion:number) => Promise<void>} putState
 * @property {(record:object) => Promise<void>} appendEvent
 * @property {(record:{key:string, result:object, expires_at:string}) => Promise<void>} appendIdempotency
 * @property {(key:string) => Promise<object|null>} getIdempotency
 * @property {(meta:object) => Promise<void>} putMeta
 */
```

- `transaction(fn)` 负责：开启 WAL → 执行 `fn(tx)` → 提交 → 清理；抛错则回滚并重新抛出。
- **`transaction(fn, { signal })`（v1.7.11，P1-B）**：`signal` 是**仓库方法参数**，不是 `Transaction` 对象的属性（`fn` 内部拿不到它）。实现须在 W1 之前与 W1–W6 的每个 `await` 之后检查 `signal.aborted`；命中则回滚并抛内部 `ABORTED`（**非本文件 §9.2 的公开码**，仅 04↔12 内部使用，12 负责映射为 `INTERNAL`）。**W7 写入 `phase='committed'` 之后不再检查**，已提交事务不得被中止撤销；此时的中止请求只记日志。
- `fn` 内部**禁止**直接调用 `ctx.storage` / 文件 API，只能通过 `tx`。
- `tx.putState` 必须再次校验 `expectedVersion`；不匹配立即抛 `STATE_VERSION_CONFLICT`。
- 事务最多包含 40 次键操作；超过抛 `STORAGE_FAILED`（防止长事务放大崩溃窗口）。
- 事务执行期间不得 `await` 网络请求或用户交互。

### 11.1 事务边界

一次状态推进必须在同一事务内完成：

1. 读取当前状态与版本；
2. 检查幂等键；
3. 计算新状态；
4. 写入新状态（`state_version = old + 1`）；
5. 写入事件记录与幂等结果；
6. 提交。

任何一步失败都回滚；不得出现“状态已更新但事件未记录”。

### 11.2 幂等

- 唯一键：`(character_id, idempotency_key)`。
- 重复请求返回首次结果（可按 12 §5.4 裁剪为摘要，字段语义不变），并标记 `duplicate: true`；`state_version` 不变。
- 同一 `event_id` 但不同 `idempotency_key` 视为不同请求，但适配层应避免这种调用。

### 11.3 乐观锁

- `saveState` 必须校验 `expectedVersion`。
- 不匹配返回 `{ok:false, code:'STATE_VERSION_CONFLICT'}`，调用方重读后最多重试 2 次。

### 11.4 协调器返回格式（`advance`）

引擎只有**一个**推进入口——02 的 `coordinator.advance`。10 与 11 由协调器在内部按 §5.4 第 10 步调用，API 层与适配层**不得**在 `advance` 之后重复调用 10/11。

```js
advance({ state, event, now, rngProvider, config }) -> {
  state,             // 新 CharacterState，state_version = 旧值 + 1
  delivery,          // 11 的交付决策，字段见 §12.4
  behavior_context,  // 10 的行为上下文，字段见 §12.4
  diagnostics: { contributions, warnings, module_ms }
}
```

- `event` 为 `null` 表示纯时间推进；其余参数均为必填，缺失抛 `INVALID_REQUEST`。
- `rngProvider` 必须是 03 的 `RandomProvider` 实例，其生命周期为：**调用方**负责提供与 `state.random` 一致的 provider，通常在每次 `advance` 前用 `RandomProvider.fromPersisted({random: state.random, character_id})` 创建；协调器消费后，在返回前执行 `draft.random = rngProvider.toPersisted()` 写回计数器；调用方信任返回的 `state.random`，不得自行再次写回。16 仿真这类同一步内连续多次 `advance` 的场景允许复用同一实例（每次返回的 `state.random` 已与 provider 同步，避免反复快进计数器），但一旦持久化或丢弃，下次必须重新 `fromPersisted`。推进失败时事务回滚、`state.random` 不落盘，调用方丢弃本次 provider、下次按持久化的 `state.random` 重新创建即可，计数器不会被持久化消耗；`serialize()` / `restore()` 只用于 `advance` 内部的"丢弃重算"（02 §5.5）。
- `config` 是 §8 的规范化配置快照。
- `runPipeline` 必须按 §5.4 注册 8 个模块：`cycle`、`sleep`、`stress`、`event`、`regulation`、`mood`、`behavior`、`delivery`。
- `elapsed > 1h` 时由协调器内部按 1h 分块，外部只调用一次 `advance`。
- 返回对象**只有** `state` / `delivery` / `behavior_context` / `diagnostics` 四个键；协调器级警告（如时钟回退）并入 `diagnostics.warnings`，不存在顶层 `warnings` 字段。`diagnostics.contributions` 为各模块 `contributions` 的合并视图，`diagnostics.module_ms` 以模块名为键记录耗时。
- 02/04/12/13 的调用示例必须与本签名一致；任何文档出现 `advance({state, event, now})` 的旧写法均视为过期。

### 11.5 存储预算与淘汰顺序

宿主配额为"账号 + 插件"256 KiB；引擎稳态合计不得超过 64 KiB。**04 与 13 必须引用本表，不得自定义数字。**

| 键 | 硬上限 | 稳态目标 | 保留 | 写入者 | 可否淘汰 |
| --- | --- | --- | --- | --- | --- |
| `state` | 8 KiB | ≤4 KiB | 1 份 | 事务提交 | 否 |
| `evlog` | 16 KiB | ≤10 KiB | 200 条 / 90 天 | `appendEvent` | 是（最后） |
| `idem` | 32 KiB | ≤20 KiB | 300 条 / 7 天 | 事务提交 | 是（其次） |
| `meta` | 24 KiB | ≤8 KiB | 1 份；`snapshots` 最多 12 条**摘要**（每条 ≤256 B） | 适配器 | 是（最先） |
| `cfg` | 4 KiB | ≤2 KiB | 1 份；只存脱敏配置，不含 `master_seed_hex` | 初始化/变更 | 否 |

- **淘汰顺序固定为 `meta.snapshots` → `idem` → `evlog`**；`state` 与 `cfg` 永不淘汰。理由：快照可重建，幂等条目会过期，事件日志是审计依据。
- 合计 >64 KiB 立即按上述顺序淘汰并追加 `STORAGE_EVICTED`；合计 >224 KiB 停止写入，返回 `STORAGE_FAILED` 并只读降级。
- 单项硬上限之和为 **84 KiB**，仅用于崩溃恢复期间的瞬时峰值，不是稳态预算；稳态目标之和为 44 KiB。
- 迁移窗口内 `meta` 允许接近其 24 KiB 硬上限（`state_backup` ≤8 KiB + `rollback_state` ≈4 KiB + 12 条摘要 ≈3 KiB + `tx_journal` ≈1 KiB），迁移结束即回落至 ≤8 KiB 稳态；该瞬时峰值不改变 64 KiB 稳态目标。
- `meta.snapshots` 只存 `{state_version, updated_at, summary}` 摘要，完整状态只允许存在于 `state` 键（迁移窗口内的 `meta.state_backup` 是唯一例外，见 §10.2.1）。
- 插件模式不保存 30 天 `history`，只用 12 条摘要；文件/SQLite 模式可另存 `history`，但同样计入 64 KiB 稳态预算。
- **主聊天绑定 fail-closed**：`primary_chat_id` 未配置时，所有写操作返回 `DEGRADED`，由管理员显式绑定（12 的 `/v1/admin/reset` 或 13 的管理工具）；禁止首次调用自动抢占成为主聊天。

### 14.1 冲突即停（强制）

模块 AI 在工作过程中一旦发现下列任一情况，**必须立即停止相关实现**，不得自行选一个方案继续：

- 本文件与模块任务书对同一字段的范围、类型、语义描述不一致；
- 两个模块对同一字段都有写入权；
- 任务书要求的输入在本文件中不存在；
- 宿主 API 无法提供任务书假设的能力。

停止后按以下格式提交《冲突报告》，由总控 AI 裁决：
